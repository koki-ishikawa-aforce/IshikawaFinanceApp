## AT-901: Gmail OAuth 連携(シナリオB Section A)

昇格時の骨子:

- 各ユーザーが「Gmail 連携」から OS 標準ブラウザで Google 同意画面を開き、`gmail.readonly` で許可 → 連携完了になる
- キャンセル・エラー時に再試行できる
- 本人以外の Google アカウントでの代理認可ができない(または警告される)
- トークン失効時: API 失敗検知 → LINE 個人 DM → アプリ経由再認可の導線(OQ-2)

## AT-902: 日次メール取込バッチ(シナリオA 日次ループ)

昇格時の骨子:

- 実際の SMBC カード利用後、翌日 0:00 のバッチで取引が自動取込される(過去5日スキャン・Gmail message ID 重複除外)
- 学習済み加盟店は自動分類、未学習は未分類フラグ
- 銀行入金の用途自動判別(勤務先入金は入金日 21日以降/前 と 25万円以上/未満 の 2 シグナル一致で給与/経費精算入金を確定、矛盾時は手動確認待ち / 貯蓄口座からの戻し)
- 銀行出金の用途自動判別(貯蓄口座への振込=シャドウ残高加算)
- バッチ完了サマリ(処理件数・成功・失敗・未分類)が確認できる

## AT-903: LINE 通知配信(シナリオA 5/5・5/10)

残るブロッカーはリマインダーの定時起動のみ(#35 / #416)。配信処理・本文生成・停止判定と、
月次レポートサマリの配信(CSV 確定イベントで発火)は #389 で実装済み。
ただしリマインダーを呼び出すエントリポイント(Lambda ハンドラー・手動起動スクリプト)は
#416 の担当で未実装のため、実機でリマインダーを確認する手段がまだ無い。
昇格は #416 の完了後に行う。

昇格時の骨子:

- 毎月 5 日から CSV 取込完了まで、共通トークルームに CSV リマインダーが毎日届く
- 夫婦両方の CSV 取込完了で、月次レポートサマリが共通トークルームに Flex Message で届き、本人サマリが各 DM に届く
- 配信ログ(payload JSON)が保存され、後からレポート値が遡及修正されても配信時点の値を参照できる
- 取込完了でリマインダーが停止する
- 単発配信失敗はスキップ(ログのみ)、連続障害はフェイルセーフメール

## AT-904: Amazon 注文突合・商品キー学習(シナリオC Phase 6)

昇格時の骨子:

- Amazon 注文確認メールと SMBC カード利用通知が金額・タイミングで突合される
- 商品カテゴリキーで学習・自動分類される(加盟店名 AMAZON.CO.JP は学習対象外)
- 突合タイムアウト 3 日(双方向): SMBC 先行なら「Amazon 注文不明」で未分類確定、Amazon 先行なら注文情報破棄

## AT-905: PDF 明細の取込(シナリオB Section F / シナリオA CSV 取込)

昇格時の骨子:

- PDF 明細をアップロードすると Claude API で CSV 変換され、以降は CSV 取込フロー(AT-301)に合流する
- 変換失敗時にユーザーへ通知され、ジョブが失敗状態になる

## AT-906: 引落予定・約定整合チェック(シナリオA 5/11・NISA)

昇格時の骨子:

- 引落予定メールから予定(金額・予定日・引落先)が抽出され、予定日に SMBC 残高減算・NISA 累計増算が自動反映される
- 約定完了メールとの金額整合が検証され、不一致でアラートが出る
- カード引落確定通知と当月取引合計の整合が検証され、不一致でアラートが出る
- 同じ引落確定通知が再取込されても SMBC 残高が二重に減らない。逆に、消込だけ済んで残高が未反映のまま失敗した場合は、再取込で残高がちょうど1回分減って回復する(#388)

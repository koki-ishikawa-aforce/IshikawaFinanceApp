## AT-105: 登録前の LINE 友だち追加が登録完了時に検知される

- 目的: アプリに登録する前に LINE 公式アカウントを友だち追加していた場合、登録完了の時点で「友だち追加済み」として扱われること(OQ-55 ③)
- 対象: `${WEB_URL}/onboarding`, `GET /api/onboarding/me`
- 実施者: 両方(登録は 1 人 1 回のため、初回オンボーディング時に実施する)
- 前提条件: AT-101 合格 / まだアプリに登録していない(ニックネーム未保存)状態であること / LINE 公式アカウントの Channel Access Token が Phase 0 セットアップ済みであること(AT-103)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | アプリを開く前に、LINE で「わりまる」公式アカウントを友だち追加する | 友だち追加が完了する | ☐ |
| 2 | アプリを開き、オンボーディングでニックネームを入力して保存する(= 登録完了) | 保存が成功する | ☐ |
| 3 | 続けて表示される手順を確認する | 「LINE 公式アカウントを友だち追加」の手順が飛ばされ、次の「共通トークルームへ参加」が表示される | ☐ |
| 4 | (可能なら)`GET /api/onboarding/me` のレスポンスを確認 | 自分の `lineOperationSettings.friendAdd` が `added` になっている | ☐ |

- 事後処理: なし
- 備考: 登録より前に届く友だち追加の通知(follow Webhook)は、宛先のユーザーがまだ存在しないため破棄される。本シナリオはその取りこぼしを登録完了時の照会が拾い直すことの確認。⚠ 手順 3 で友だち追加の手順が表示された場合、照会が失敗した可能性がある(登録自体は成功する仕様)。その場合は NG とせず「照会失敗」と記録したうえで、いったん公式アカウントをブロック → 解除して友だち追加をやり直すと、follow Webhook 経由で記録される

## AT-106: 共通トークルームへの招待が在籍確認を通ってから登録される

- 目的: LINE 公式アカウントを招待したトークルームが、夫婦のいずれかが在籍しているものであることを確認したうえで通知の送り先として登録されること。第三者のトークルームが送り先にならないこと(OQ-55 ① / #371)
- 対象: `POST /webhook/line`(join), `${WEB_URL}/onboarding`, `GET /api/onboarding/me`
- 実施者: どちらか(共通トークルームは世帯にひとつのため 1 回で足りる)
- 前提条件: AT-101 合格(夫婦とも登録済み) / まだ共通トークルームが登録されていない状態であること / LINE 公式アカウントの Channel Access Token が Phase 0 セットアップ済みであること(AT-103)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 夫婦以外のメンバーだけのグループ(自分が参加していない、または夫婦がいないグループ)に「わりまる」公式アカウントを招待する | 招待は成立するが、送り先として登録されない | ☐ |
| 2 | `GET /api/onboarding/me` またはセットアップ画面を確認 | 共通トークルームが未登録のまま(「共通トークルームへ参加」の手順が残っている) | ☐ |
| 3 | 手順 1 のグループから公式アカウントを退出させ、夫婦の共通トークルームに招待し直す | 招待が成立する | ☐ |
| 4 | セットアップ画面を再ロードする | 「共通トークルームへ参加」の手順が完了として表示される | ☐ |
| 5 | (可能なら)`GET /api/onboarding/me` のレスポンスを確認 | 共通トークルームIDが手順 3 のトークルームのものになっている | ☐ |

- 事後処理: 手順 1 で使ったグループから公式アカウントが退出済みであることを確認する
- 備考: 手順 1 の「夫婦がいないグループ」を用意できない場合は、この手順を省略して手順 3 以降だけ実施し、備考に「取り違え防止は未検証」と記録する。⚠ 手順 4 で完了にならない場合、在籍照会が失敗した可能性がある(通信断・Channel Access Token の設定漏れ)。その場合は NG とせず「照会失敗」と記録したうえで、公式アカウントをいったん退出させて招待し直す。招待の通知(join Webhook)は招待の瞬間にしか届かず再送されないため、待っても登録されない

## AT-107: 両者のオンボーディング完了で運用開始が発火し、テストメッセージが届く

- 目的: 夫婦の両方がオンボーディング(Phase2)を完了した時点で運用開始となり、共通トークルームに「わりまる」からのテストメッセージが 1 通だけ届くこと(シナリオB Phase4 / 08f §2「運用開始を発火する」「通知機能を有効化する」)
- 対象: `${WEB_URL}/onboarding`, `GET /api/onboarding/spouse-completion`, LINE の共通トークルーム
- 実施者: 両方(完了タイミングをずらして実施)
- 前提条件: AT-105 合格(夫婦とも LINE 公式アカウントを友だち追加済み) / AT-106 合格(共通トークルームが登録済み) / 夫婦の一方が未完了の状態を作れること(初回オンボーディング時に実施するのが自然)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 先に完了した側でオンボーディングを完了する | 完了できる。この時点では共通トークルームにテストメッセージは届かない | ☐ |
| 2 | 先に完了した側でセットアップ画面を再ロードする | テストメッセージは届かないまま(片方だけでは運用開始しない) | ☐ |
| 3 | もう一方がオンボーディングを完了する | 共通トークルームに「割まるのテスト送信です🎉」で始まるメッセージが 1 通届く | ☐ |
| 4 | 両者でセットアップ画面を再ロードする | テストメッセージが増えない(同じメッセージが繰り返し届かない) | ☐ |

- 事後処理: なし
- 備考: 手順 3 でメッセージが届かない場合、届かない原因は「運用開始が発火していない」か「LINE への送信が失敗した」のどちらか。⚠ 相方の完了は自動では検知されないため(画面ロード時のみ判定)、手順 3 のあと数分待っても届かないときは、まず両者でセットアップ画面を再ロードしてから判定する。再ロードしても届かない場合のみ NG とする。手順 4 で 2 通目が届いた場合は冪等性の不具合として NG

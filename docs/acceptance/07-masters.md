## AT-601: カテゴリの追加・改名・削除(移動先選択・学習リマップ)

- 目的: 追加カテゴリの CRUD と、削除時の移動先(カテゴリ+費用区分)選択・配下取引移動・学習ルールリマップが動作すること(C5-1, C5-2)。規定4種が保護されていること
- 対象: `${WEB_URL}/settings`(カテゴリタブ)
- 実施者: どちらか
- 前提条件: 追加カテゴリ `TEST-DIY` と、それに分類された取引 2 件・学習ルール 1 件(AT-202/206 で作成)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 追加カテゴリ `TEST-DIY2` を新規作成 | 一覧に追加される(個人別) | ☐ |
| 2 | `TEST-DIY2` を `TEST-趣味` に改名 | 改名される。取引・学習データへの副作用なし(C5-5) | ☐ |
| 3 | `TEST-DIY` の削除を開始 | 移動先カテゴリ+費用区分の選択ダイアログが表示され、配下取引の件数警告が出る | ☐ |
| 4 | 移動先=住居・光熱・通信 / 費用区分=世帯 を選択して削除確定 | `TEST-DIY` が消え、配下取引 2 件がカテゴリ=住居・光熱・通信/費用区分=世帯 に移動している | ☐ |
| 5 | 学習ルールを確認(AT-208 の方法) | `TEST-DIY` を参照していたルールが移動先にリマップされている | ☐ |
| 6 | ダッシュボード・過去レポートを確認 | リアルタイム再計算で削除カテゴリの表示が消え、移動先に集計されている(C5-3) | ☐ |
| 7 | 規定4種(住居・光熱・通信/食費/娯楽/その他)の削除・改名を試す | 操作できない(UI 非表示または API 拒否) | ☐ |

- 事後処理: `TEST-趣味` を削除(配下取引なしなら移動先選択のみで完了)。手順 4 で移動した取引が `TEST-` 取引なら削除
- 備考: 依存 API `POST /api/categories`, `PUT /api/categories/:id`, `POST /api/categories/:id/deletion-requests`, `DELETE /api/categories/:id`

## AT-602: 経費種別の追加・削除と規定5種の固定

- 目的: 追加経費種別の CRUD と削除時の移動(カテゴリと同構造: C5-4)、規定5種の保護を確認する
- 対象: `${WEB_URL}/settings`(経費種別タブ)
- 実施者: どちらか
- 前提条件: 追加経費種別 `TEST-種別`(AT-206 で作成)と、それに分類された経費取引 1 件

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 追加経費種別を新規作成(上限あり 3,000 円で作成) | 一覧に追加され、月次上限も設定される(P2-E4) | ☐ |
| 2 | `TEST-種別` の削除を開始 | 移動先経費種別(+費用区分)の選択ダイアログが表示される | ☐ |
| 3 | 移動先=その他経費 を選択して削除確定 | 配下取引が「その他経費」に移動し、学習ルールもリマップされる | ☐ |

## AT-603: 月次上限変更と当月按分の再計算

- 目的: 月次上限の変更が保存でき、当月の経費按分が自動再計算されること(P2-E6 / OQ-20)
- 対象: `${WEB_URL}/settings`(月次上限タブ), `${WEB_URL}/expense-settlement`
- 実施者: どちらか(seed 値の個人差確認は両方)
- 前提条件: 当月に上限のある経費種別の取引があること(AT-304 の `TEST-ジム` 7,000 円を流用可)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 月次上限タブで自分の上限一覧を確認 | 自分のロールに応じた値が表示される(夫: AI 利用費 10,000 / 妻: 3,000 — AT-101 の間接確認) | ☐ |
| 2 | ジムの上限を 5,000 → 8,000 円に変更して保存 | 保存成功 | ☐ |
| 3 | 精算画面で当月のジム累計を確認 | 按分が再計算され、7,000 円全額が経費充当・子取引(個人 2,000 円)が解消されている | ☐ |
| 4 | 上限を 5,000 円に戻す | 再度按分され、5,000 円充当+個人 2,000 円の状態に戻る | ☐ |
| 5 | 無制限の種別(交通費)の表示を確認 | 「無制限」として表示され、按分対象にならない | ☐ |

- 事後処理: 上限を seed 値(実運用値)に戻す。`TEST-ジム` 取引を削除
- 備考: 依存 API `GET /api/monthly-limits`, `PUT /api/monthly-limits`

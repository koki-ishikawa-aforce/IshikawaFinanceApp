# 04. 月次サイクル(AT-3xx)

一次資料: [docs/domain/04-scenario-a-monthly-cycle.md](../domain/04-scenario-a-monthly-cycle.md)

CSV 取込 → 一括分類 → CSV 確定 → 経費按分 → 精算入金突合 → 最終確定、の書き込みフルフロー。

> ⚠ 実施上の注意
>
> - 月次レポート・精算サイクルの状態を変更するため、**実運用サイクルと重ならない対象月**(運用開始前の過去月など)で実施するか、実運用の月次サイクルそのものを受入テストを兼ねて実施する
> - メール自動取込(日次バッチ)は未稼働のため、取引の入口は CSV アップロードと手動登録のみ(AT-902 参照)
> - AT-301 → AT-302 → AT-303 → AT-304 → AT-305 → AT-306 → AT-307 の順に連続実施する前提で書かれている

---

## AT-301: カード CSV 取込(検証・候補確認・重複除外)

- 目的: SMBC カード CSV のアップロード → 形式検証 → 候補確認 → 取込確定が動作し、既存取引と重複しないこと
- 対象: `${WEB_URL}/imports`
- 実施者: 両方(それぞれ自分のカード明細で)
- 前提条件: SMBC マイページからダウンロードした対象月のカード CSV(または同形式のテスト CSV)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 取込画面で「カード利用明細」を選び CSV をアップロード | ジョブが受付済み → 形式検証中 → 取込中と進行する | ☐ |
| 2 | 候補一覧を確認 | CSV の取引が候補として一覧表示される | ☐ |
| 3 | 候補から 1 件を除外して取込確定 | 除外した 1 件を除いた件数で取込が確定する | ☐ |
| 4 | 取引一覧を確認 | 取込済みの取引が表示される。学習済み加盟店は自動分類、未学習は未分類 | ☐ |
| 5 | **同じ CSV をもう一度アップロード**して確定まで進める | 日付・金額・加盟店名の3項一致で重複が除外され、二重計上されない | ☐ |
| 6 | 不正な形式のファイル(テキスト等)をアップロード | 形式検証エラーとなり取込が中止される(ジョブが「失敗」表示) | ☐ |

- 事後処理: テスト用 CSV(実明細でない場合)で取り込んだ取引は削除する。実明細ならそのまま実運用データとして残す
- 備考: 依存 API `POST /api/imports/csv`, `GET /api/imports/:batchId/candidates`, `PUT /api/imports/:batchId/confirm`, `GET /api/imports/status`。PDF アップロード(Claude API 変換)は AT-905 参照

- 対象: `${WEB_URL}/imports`, `${WEB_URL}/transactions`
- 実施者: どちらか

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 取込完了画面のサマリを確認 | 「新規 N 件、自動分類 N 件、未分類 N 件」の内訳が表示される | ☐ |
| 2 | 一括分類を開始する | 一括分類セッションが起動し、未分類取引が加盟店ごとにまとめて表示される | ☐ |
| 3 | 複数の加盟店に分類(カテゴリ/費用区分/経費種別)を割り当てて一括保存 | 対象取引がすべて分類され、加盟店ごとに学習ルールが一括登録される | ☐ |

- 目的: 経費種別の月次上限を超えた取引が、上限充当分と個人費用の子取引に自動分割されること(OQ-20 / シナリオC Step 6-A)
- 対象: `${WEB_URL}/expense-settlement`, `${WEB_URL}/transactions`
- 実施者: どちらか
- 前提条件: 対象月の自分のジム経費累計が 0 円であること(上限 5,000 円を仮定)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | `TEST-ジム` 7,000 円の取引を登録し、費用区分=経費(会社)/経費種別=ジム に分類 | 分類が保存される | ☐ |

## AT-305: 経費精算入金の突合(一致・不足・過剰)

- 目的: 精算入金額と確定経費合計の突合 3 ケースが仕様どおり動作すること(シナリオA 5/15)
- 対象: `${WEB_URL}/expense-settlement`
- 実施者: どちらか
- 前提条件: AT-303 で対象月のサイクルが「CSV確定済み」、経費(会社)取引が存在すること(例: 確定経費合計 5,000 円)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 入金待ち一覧を確認(`GET /api/expense-settlement/deposits/awaiting` 相当の画面) | 対象月の精算が入金待ちとして表示される | ☐ |
| 2 | **一致ケース**: 確定経費合計と同額の入金を登録 | 全額認定され、不認定分が発生しない | ☐ |
| 3 | **不足ケース**(別サイクルまたはやり直しで): 経費合計より少ない入金を登録 | 不足分が「個人(本人)」費用として対象月に遡及計上される | ☐ |
| 4 | **過剰ケース**: 経費合計より多い入金を登録 | 超過分が「経費精算とは別の入金」として記録される | ☐ |

- 事後処理: テストで登録した入金・遡及計上された個人費用取引を削除または訂正する。3 ケースを同一月で試す場合はサイクルのやり直し可否を確認し、できなければケースごとに別のテスト月を使う
- 備考: 依存 API `POST /api/expense-settlement/deposits`, `GET /api/expense-settlement/deposits/awaiting`。銀行入金メールの自動判別(入金日 21日以降/前 と 25万円以上/未満 の 2 シグナル判定)は未稼働のため入金は手動登録(AT-902 参照)

## AT-308: 明細 CSV の取得手順ガイド(外部ブラウザ起動・月パラメータ)

- 目的: 取込画面の取得手順ガイドから公式サイトが**外部ブラウザ**で開き、カードは対象月の明細に直接到達できること
- 対象: `${WEB_URL}/imports`
- 実施者: どちらか
- 前提条件: LINE アプリ内(LIFF)で開いていること。三井住友カード・SMBC ダイレクトのログイン情報が手元にあること

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 取込画面を開く | カード・銀行それぞれの「取得方法」が畳まれた状態で表示される | ☐ |
| 2 | 「三井住友カード…の取得方法」を開く | 3 ステップの手順と、対象月を示す案内(「2026年7月分の明細ページが開きます」)が表示される | ☐ |
| 3 | 月送りで対象月を変え、再度案内を読む | 案内の月が選択中の対象月に追随する | ☐ |
| 4 | 「三井住友カードの明細ページを開く」を押す | **LIFF 内ではなく OS 標準ブラウザ**が起動し、選択中の対象月の利用明細が開く | ☐ |
| 5 | アプリ(LIFF)に戻る | 取込画面が元の対象月のまま復帰し、続けて CSV をアップロードできる | ☐ |

| 7 | 「SMBC ダイレクトを開く」を押す | OS 標準ブラウザで SMBC ダイレクトの SP サイトが開く(月は指定されない) | ☐ |

- 事後処理: なし(閲覧のみ。ブラウザからログアウトする)
- 備考: 外部ブラウザ起動は `liff.openWindow({ external: true })`。LIFF 外(通常ブラウザ)で開いた場合は別タブで開く。銀行側は URL に月・表示範囲が現れないため月指定ができない(OQ-29)

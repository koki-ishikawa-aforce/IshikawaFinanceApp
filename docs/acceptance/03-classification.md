## AT-201: 取引の手動登録・編集・削除

- 目的: 取引 CRUD が一通り動作すること
- 対象: `${WEB_URL}/transactions`
- 実施者: どちらか
- 前提条件: AT-002 合格

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 取引一覧で新規登録を開き、加盟店 `TEST-コーナン`・金額 1,500 円・当日日付で登録 | 登録が成功し一覧に表示される | ☐ |
| 2 | 登録直後の分類状態を確認 | カテゴリ=未分類、費用区分=本人の個人、経費種別=なし(C1-1 の初期値) | ☐ |
| 3 | ダッシュボードを開く | 「未分類: N件」が 1 増えている(C1-4) | ☐ |
| 4 | 取引を編集(金額を 1,600 円に変更)して保存 | 変更が反映される | ☐ |
| 5 | 取引を削除 | 一覧から消え、ダッシュボードの未分類件数が戻る | ☐ |

- 事後処理: 手順 5 で削除済み。残っていれば `TEST-` 取引を削除する
- 備考: 依存 API `POST /api/transactions`, `PUT /api/transactions/:id`, `DELETE /api/transactions/:id`

## AT-202: 未分類取引の3軸修正と学習ルール即時登録

- 目的: 1 画面で 3 軸(カテゴリ/費用区分/経費種別)を修正でき、保存で学習ルールが即時登録されること(C2-1, C2-3)
- 対象: `${WEB_URL}/transactions`
- 実施者: どちらか
- 前提条件: 未分類のテスト取引 1 件(なければ AT-201 手順 1 で `TEST-アニタイム` 7,000 円を作成)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 未分類取引の修正画面を開く | 3 軸が 1 画面に表示され、未分類軸に赤マーカー等の誘導がある | ☐ |
| 2 | カテゴリ=その他 / 費用区分=経費(会社) / 経費種別=ジム に変更して保存 | 保存成功、取引が分類済みになる | ☐ |
| 3 | 学習ルール一覧(AT-208 参照)を確認 | `TEST-アニタイム` のルール(カテゴリ・費用区分・経費種別のフィールド独立)が即時登録されている | ☐ |
| 4 | 同じ加盟店 `TEST-アニタイム` で新規取引を登録 | 学習ルールにより自動分類される(未分類にならない) | ☐ |

- 事後処理: 手順 4 の取引と手順 1 の取引を削除。学習ルールは AT-207 で無効化を検証してから整理する(削除 UI がない場合は無効化で代替)
- 備考: 依存 API `PUT /api/transactions/:id/classify`, `GET /api/classification/merchant-rules`。経費(会社)を選ぶと AT-304(按分)の前提データにもなる

## AT-203: 過去未分類の遡及一括再分類

- 目的: 学習登録時に本人の過去未分類取引へ確認ダイアログ経由で遡及適用できること(C2-4)
- 対象: `${WEB_URL}/transactions`
- 実施者: どちらか
- 前提条件: 同一加盟店 `TEST-スーパーA` の未分類取引を 3 件作成しておく(日付を数日ずらす)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 3 件のうち 1 件を修正(カテゴリ=食費 / 費用区分=世帯)して保存 | 「過去にも未分類の TEST-スーパーA 取引が 2 件あります。まとめて変更しますか?」相当の確認が表示される | ☐ |
| 2 | 「はい」を選択 | 残り 2 件も食費/世帯に一括再分類される | ☐ |
| 3 | 再分類の対象範囲を確認 | 分類済みの取引・配偶者の取引には影響していない | ☐ |

- 事後処理: `TEST-スーパーA` 取引 3 件を削除し、学習ルールを無効化・整理
- 備考: 依存 API `GET /api/classification/retroactive-candidates`, `POST /api/classification/retroactive-candidates/apply`

## AT-204: 既存学習ルールの上書き確認分岐

- 目的: 既存ルールと異なる分類へ修正した際「以後このルールに従いますか?」の分岐(今回のみ/上書き)が機能すること(C3-5)
- 対象: `${WEB_URL}/transactions`
- 実施者: どちらか
- 前提条件: AT-202 で `TEST-アニタイム` 等の学習ルールが存在すること

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 学習済み加盟店で新規取引を登録(自動分類される) | 既存ルールどおり自動分類 | ☐ |
| 2 | その取引のカテゴリを別の値に修正して保存 | 「以後この分類にしますか?」相当の確認が表示される | ☐ |
| 3 | 「今回のみ」を選択 | 取引は修正されるが、学習ルールは元のまま | ☐ |
| 4 | もう一度別の取引で同修正を行い「上書き」を選択 | 学習ルールが新しい分類に上書きされ、以後の取引は新ルールで自動分類される | ☐ |

- 事後処理: テスト取引を削除。上書きしたルールが実運用に不要なら無効化・整理
- 備考: ルール一覧(AT-208)で上書き前後の値を確認すると確実

## AT-207: 「この加盟店は学習しない」無効化

- 目的: 学習無効化フラグを立てた加盟店は以後常に未分類で取り込まれること(C3-6)
- 対象: `${WEB_URL}/transactions`
- 実施者: どちらか
- 前提条件: 学習済みのテスト加盟店が 1 つあること(AT-202 の `TEST-アニタイム` 等)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 対象加盟店の取引修正画面で「この加盟店は学習しない」をチェックして保存 | 保存成功 | ☐ |

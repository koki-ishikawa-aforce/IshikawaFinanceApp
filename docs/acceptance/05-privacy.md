# 05. プライバシー3段階ルール(AT-4xx)

割まるの中核不変条件。**すべて夫婦両方の実機 LIFF で実施必須**(片側だけでは合格にしない)。

| 段階 | ルール |
| --- | --- |
| 世帯 | 夫婦双方にフルオープン(明細・金額すべて) |
| 個人 | 本人はフル可視、配偶者には**合計のみ**(明細不可視) |
| 経費(会社) | **本人のみ**可視(配偶者には合計も不可視) |

検証は Query 層の ViewerContext を通した実挙動で行う。ダッシュボード・取引一覧・月次レポートの 3 画面すべてで漏れを確認する。

> 実施のコツ: 事前に金額を素数など特徴的な値にした `TEST-` 取引を作ると、合計への混入有無を判別しやすい(例: 世帯 1,111 円 / 夫個人 2,221 円 / 夫経費 3,331 円)。

---

## AT-401: 世帯費用の双方フル可視

- 目的: 世帯費用の取引は夫婦どちらからも明細レベルで見えること
- 対象: `${WEB_URL}/transactions`, `${WEB_URL}/`, `${WEB_URL}/reports`
- 実施者: 両方

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 夫が `TEST-世帯買物` 1,111 円を登録し、費用区分=世帯 に分類 | 登録成功 | ☐ |
| 2 | 夫の画面で取引一覧・ダッシュボードを確認 | 明細・集計に表示される | ☐ |
| 3 | **妻の実機**で取引一覧を確認 | `TEST-世帯買物` が明細(加盟店名・金額・日付)まで見える | ☐ |
| 4 | 妻の画面でダッシュボード・レポートの世帯集計を確認 | 1,111 円が世帯費用に含まれている | ☐ |

- 事後処理: `TEST-世帯買物` を削除
- 備考: —

## AT-402: 個人費用は相手に合計のみ

- 目的: 個人費用は本人にフル可視、配偶者には合計金額のみで明細が見えないこと
- 対象: `${WEB_URL}/transactions`, `${WEB_URL}/`, `${WEB_URL}/reports`
- 実施者: 両方(夫→妻の方向で実施後、妻→夫の方向も実施)

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 夫が `TEST-夫個人` 2,221 円を登録し、費用区分=個人(夫) に分類 | 登録成功 | ☐ |
| 2 | 夫の画面で確認 | 明細・集計とも見える | ☐ |
| 3 | **妻の実機**で取引一覧を確認 | `TEST-夫個人` の**明細が表示されない**(加盟店名・個別金額が見えない) | ☐ |
| 4 | 妻の画面でダッシュボード・レポートを確認 | 夫の個人費用**合計**には 2,221 円が含まれて見える。ダッシュボードの行の呼び名は、夫が設定でニックネームを登録していればそのニックネーム、未登録なら役割名(Honey/Darling)になる(#596) | ☐ |
| 5 | 方向を入れ替えて(妻が登録・夫が確認)手順 1〜4 を実施 | 同様の結果 | ☐ |

- 事後処理: 双方の `TEST-` 個人取引を削除
- 備考: 合計のみ可視の「合計」がどの画面に出るか(ダッシュボード/レポート)は実装に合わせて確認。API を直接叩ける場合は `GET /api/transactions` のレスポンスに相手の個人明細が**含まれない**ことも確認すると強い(UI 非表示だけでは不合格)

## AT-403: 経費(会社)は本人のみ可視

- 目的: 経費(会社)の取引・集計が配偶者には合計すら見えないこと
- 対象: `${WEB_URL}/transactions`, `${WEB_URL}/expense-settlement`, `${WEB_URL}/reports`
- 実施者: 両方

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 夫が `TEST-夫経費` 3,331 円を登録し、費用区分=経費(会社)/経費種別=その他経費 に分類 | 登録成功 | ☐ |
| 2 | 夫の画面で精算画面・レポートを確認 | 経費として累計・集計に表示される | ☐ |
| 3 | **妻の実機**で取引一覧・ダッシュボード・レポートを確認 | `TEST-夫経費` の明細も**合計への寄与も一切見えない**(妻側のどの集計にも 3,331 円が現れない) | ☐ |
| 4 | 妻の実機で精算画面を確認 | 夫の精算サイクル・経費累計が見えない(自分の分のみ表示) | ☐ |
| 5 | 方向を入れ替えて(妻が登録・夫が確認)実施 | 同様の結果 | ☐ |

- 事後処理: 双方の `TEST-` 経費取引を削除(按分が発生していれば子取引も)
- 備考: 経費精算コンテキスト全体が「本人のみ」領域。API 直接確認ができる場合は `GET /api/expense-settlement` 系が相手のデータを返さないことも確認

## AT-404: 残高の配偶者可視範囲

- 目的: 残高は本人のみ可視、ただし別銀行貯蓄+NISA 累計は**合計のみ**配偶者可視であること(P2-B5)
- 対象: `${WEB_URL}/balances`
- 実施者: 両方

| # | 操作 | 期待結果 | ☐ |
| --- | --- | --- | --- |
| 1 | 夫の画面で残高一覧を確認 | 自分の SMBC 残高・別銀行貯蓄・NISA 累計・カード未払金が見える | ☐ |
| 2 | 夫の画面で妻の残高の表示を確認 | 妻の SMBC 残高・カード未払金は見えない。妻の「別銀行貯蓄+NISA の合計」だけが見える | ☐ |
| 3 | 妻の実機で同様に確認 | 対称に同じ結果 | ☐ |
| 4 | 世帯合計表示を確認 | 双方に同じ世帯合計が表示され、内訳の可視範囲は上記ルールに従う | ☐ |

- 事後処理: なし(読み取りのみ)
- 備考: 依存 API `GET /api/balances`, `GET /api/balances/total`

## 1. 目的とスコープ

### 1.1 目的

Phase 3 で確定した家計分析・残高資産推移管理・取引取込・自動分類学習・経費精算・オンボーディング認証・通知配信・マスタ管理の 8 コンテキストに対し、**特に分析系（家計分析・残高資産推移管理）が UI/UX と密に連動する** ため、画面レイアウト・ナビゲーション・操作体系を Phase 4 戦術的設計の前に確定させる。

家計分析の集約境界・型定義は「画面が要求するデータ契約」から逆算される性質を持つため、ここで決まる UX は Phase 4 の集約・値オブジェクト設計に直接反映される。

### 1.3 スコープ外（Phase 4 以降に送る）

- 実装言語での型定義（TypeScript・Zod）
- API 設計（Hono ルート・OpenAPI）
- 永続化（Neon Postgres スキーマ）
- 状態管理ライブラリ選定（TanStack Query 等）
- UI ライブラリ実体選定（shadcn/ui / Mantine / 自前 等）
- アプリ名（spec 作成時点では未定、本 spec 中は「（仮）」または無冠で表記 → 2026-07-06 に「わりまる」で確定、OQ-37）

### 1.4 設計原則

- **2 人ユーザー前提**: ロールは Honey（夫）/ Darling（妻）の 2 つ固定。世帯管理者は不在
- **ニックネーム優先表示**: 通常画面はニックネーム表示。ロール名は設定画面・オンボーディングで明示
- **プライバシー 3 段階の徹底**（01-overview §7）: 世帯=フルオープン / 個人=本人明細・相手合計のみ / 経費(会社)=本人のみ
- **LIFF スマホ縦画面前提**: 横画面想定なし。タブレット/PC は表示はできるがレイアウト最適化はしない
- **キュート × ペア感**: パステル配色 + 角丸 + 丸ゴシック。夫婦のテーマカラーが対になる
- **「上限を意識させない」**: 経費精算管理は進捗バーなし、合計のみ
- **アラート優先順位**: 未分類取引 > CSV 未取込 > OAuth 失効 > その他

## 5. ダッシュボード仕様

### 5.1 構造（縦スクロール）

1. **ヘッダ**: 月セレクター / レポートバッジ / 設定 / ロール pill
2. **世帯-個人 2-way 切替**: セグメントコントロール `[🏠 世帯][👤 個人]`

### 5.2 KPI 4 枚の定義

| # | ラベル | 内容 | 補助情報 | 備考 |
|---|---|---|---|---|
| 1 | 📊 今月支出 | 当月の費用区分合計（世帯/個人モードで切替） | 前月比 | 経費(会社) は除外 |

### 5.3 ドーナツチャート

## 7. 取引一覧画面

### 7.1 構造

| 要素 | 配置 |
|---|---|
| ヘッダ（月切替・⚙️） | 上 |
| 検索バー | ヘッダ下 |

| ボトムタブ | 下 |

### 7.2 取引アイテムの表示要素

- カテゴリ色のサイドバー（左 6px）
- 加盟店名（太字）
- 時刻 + 出典（SMBC通知メール / Amazon突合 / 引落確定通知 / CSV取込）
- カテゴリ chip + 費用区分 chip
- 金額（右寄せ太字）
- 未分類は黄色背景 + ⚠️アイコン + 左ボーダーオレンジ

### 7.3 プライバシー適用

- 自分の取引: 全表示
- パートナーの世帯取引: 表示
- パートナーの個人取引: **「（パートナー名）の取引（合計のみ）」** と 1 行で表示、明細は不可視
- パートナーの経費(会社): **完全非表示**（リストに現れない）

### 7.4 編集モーダル（A 案: シンプル統合）

| セクション | 内容 |
|---|---|
| 取引情報（読み取り専用） | 加盟店名 / 日時 / 金額 |
| カテゴリ | select（4 + 追加カテゴリ + ＋新規） |
| 費用区分 | 4 ボタン（世帯 / 個人(自分) / 個人(相手, disabled) / 経費(会社)） |
| 経費種別 | select（経費(会社) 選択時のみアクティブ） |
| 学習スイッチ | トグル: "🎓 自動分類を学習する" + 説明テキスト |
| 過去遡及（ネスト） | チェック: "↳ 過去の同店未分類 N 件にも適用"（学習 ON 時のみ） |
| ボタン | キャンセル / 保存 |

**学習 OFF**: この取引のみ変更、加盟店学習データは更新しない（M-1: 学習無効化）。
**過去遡及 ON**: 同じ加盟店の過去未分類取引を一括分類（J-3: 過去未分類への遡及適用）。
**既存ルール上書き** (L-4): 同じ加盟店に既存学習がある場合、保存ボタン上に赤い警告 + 上書き確認。

### 9.3 個別詳細（別銀行貯蓄の例）

1. ヘッダ（戻る + 銀行名）
2. 残高 hero（鮮度警告付き）
3. **手入力ボタン 2 つ**（別銀行貯蓄のみ）
   - 💸 取り崩しを記録
   - ✎ 残高を補正
4. 残高推移グラフ（単線、12/6/3 ヶ月切替）
5. 取引履歴（自動加算 + 手入力混在）

三井住友銀行 / 三井住友カード / NISA の詳細は同構造、手入力ボタンなし。

### 9.4 時系列グラフ仕様

- **Y 軸目盛**: 「100万 / 200万 / 300万」形式（万単位、丸め）
- **X 軸目盛**: 月（"6月", "8月", ... "5月"）
- **直近値ラベル**: 青タグ + full 表記（例: ¥2,475,400）
- **グリッド線**: 水平のみ、薄い `#dde6f0`
- **期間切替**: 12 ヶ月 / 6 ヶ月 / 3 ヶ月
- **ジャンプポイント**: 振込（自動加算）= 青丸 + 白枠、取り崩し（手入力）= オレンジ丸 + 白枠
- **線の本数**: 資産推移グラフ = 3 線（資産合計・貯蓄・NISA）。未払金は別表示

### 10.3 取込中・取込結果

**取込中**: 内部ステップ（PDF 変換 / パース / 重複除外 / 自動分類）は **非表示**。「📄 ファイル名」+ シンプルな「⋯ 取り込み中…」+ 「完了まで 1〜2 分」表示のみ。

**取込結果**:
- ✓ 大きな完了アイコン
- 件数内訳: 新規取込 / 重複でスキップ / 未分類で取込
- 月次レポート昇格通知（"◯月の月次レポートが「CSV確定」に昇格しました"）
- ボタン: 未分類を確認 / 完了

### 12.1 通知 5 種

| # | 通知 | 経路 | 宛先 | タイミング |

### 12.3 Flex Message の構造

- **ヘッダ**: カラー帯（通知種別ごとに色分け）+ 状態バッジ + タイトル
- **本文**: サマリ数字 + カテゴリ内訳（簡略）+ アラート（あれば）
- **CTA ボタン**: テーマ色グラデ（自分の DM ではテーマ色 / 共通トークルームでは中立色）

### 12.4 表示原則（01-overview §6.4 準拠）

- LINE 上に **明細を載せない**。サマリ + アプリリンクのみ
- 経費(会社) は LINE 通知に含めない（プライバシー）

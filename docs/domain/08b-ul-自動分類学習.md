# ユビキタス言語: 自動分類・学習

> 親: [docs/domain/08-ubiquitous-language.md](./08-ubiquitous-language.md)
> サブドメイン: Core（07-bounded-contexts.md §2.2）

## 責務

取引取込から渡された取引候補に対し、per-user の memorization 学習データ（加盟店ルール）を引いてカテゴリ・費用区分・経費種別を当てる。ユーザーの手動修正を学習データに即時反映し、過去未分類の遡及（J-3）・既存ルール上書き（L-4）・学習無効化（M-1）・Amazon 突合タイムアウトを管理する。F-1（完全個人別）・T-2（フィールド独立）を一貫して守る。

> **X-1（Amazon 商品キー学習）は取り下げ（2026-08-23 / #391・#572）**。商品カテゴリで学習する仕組みは持たない（Amazon 注文確認メールに商品カテゴリが含まれないことが実メール調査で判明したため）。加盟店名「AMAZON.CO.JP」を加盟店学習の対象外とする扱いは維持すると決定済み（OQ-18 改訂 / #581）。Amazon の取引はどの学習ルールにも記録されず毎回手動で分類することになる。Amazon 注文と SMBC 通知の突合そのもの（双方向 3 日のタイムアウトを含む）は残る。

## 1. データ（data）

```
// このコンテキストの中核は per-user の学習ルール群と、ルックアップ結果としての分類済み／未分類取引である。
// 取引のライフサイクルは家計分析が主担当だが、未分類 ↔ 分類済みの状態遷移トリガーは本コンテキストにある。

// クロスコンテキスト参照（ID のみ借用）
// referenced from: オンボーディング・認証
data ユーザーID = 文字列  // LINE userID

// referenced from: マスタ管理
data カテゴリID = 文字列
data 経費種別ID = 文字列

// referenced from: 取引取込
data 取引候補ID = 文字列  // 分類前のソースを示す ID

// referenced from: 家計分析
data 取引ID = 文字列

// 共通語彙の借用（08 §2 と一致）
data 加盟店名 = 文字列  // NFKC 正規化済み
data 費用区分 = 世帯 OR 個人(夫) OR 個人(妻) OR 経費(会社)

// 学習ルールの宣言: 加盟店名ベース（通常加盟店）
// T-2 によりカテゴリ／費用区分／経費種別を別マッピングで持つ。
// F-1 により ユーザーID で完全に分離する。
// M-1 により「学習しない」状態と通常状態を OR で表現する。

// aggregate root
data 加盟店学習ルール = 有効加盟店学習ルール OR 学習無効化加盟店ルール

data 有効加盟店学習ルール = ユーザーID
   AND 加盟店名
   AND カテゴリ参照
   AND 費用区分参照
   AND 経費種別参照
   AND 最終更新日時

data 学習無効化加盟店ルール = ユーザーID
   AND 加盟店名
   AND 無効化日時
// 「この加盟店は学習しない」チェック。以後ルックアップでは学習無効化扱いとなり常に未分類で取り込む。

// T-2 のフィールド独立: 各参照は「学習済み」または「未学習」のいずれか
data カテゴリ参照 = 学習済みカテゴリ OR カテゴリ未学習
data 学習済みカテゴリ = カテゴリID
data カテゴリ未学習 = なし

data 費用区分参照 = 学習済み費用区分 OR 費用区分未学習
data 学習済み費用区分 = 費用区分
data 費用区分未学習 = なし

data 経費種別参照 = 学習済み経費種別 OR 経費種別未学習
data 学習済み経費種別 = 経費種別ID
data 経費種別未学習 = なし

// 学習ルールは加盟店ベースのみ。加盟店名「AMAZON.CO.JP」は学習対象外で、
// 代わりの学習経路（X-1 Amazon商品キー学習ルール）は取り下げた（2026-08-23 / #391・#572）。
// 除外は維持すると決定済み（OQ-18 改訂 / #581）。

// 取引候補のルックアップ結果としての分類済み／未分類取引
// 本コンテキストでは「分類が確定した取引」と「未分類のまま渡される取引」を区別して下流に渡す。
// referenced from: 家計分析（取引のライフサイクルは家計分析側が主担当）

data 分類結果 = 自動分類済み取引 OR 未分類取引

data 自動分類済み取引 = 取引ID
   AND 加盟店名
   AND カテゴリID
   AND 費用区分
   AND 適用済み経費種別ID?
   AND 分類根拠
// 経費種別は経費(会社) のときのみ適用される値（? は業務上適用されない場合のみ許容）

data 未分類取引 = 取引ID
   AND 加盟店名
   AND 未分類理由
   AND デフォルト費用区分

data 未分類理由 = 加盟店ルール未学習 OR Amazon商品情報判定不能 OR Amazon突合タイムアウト OR 学習無効化適用
// Amazon商品キー未学習 は X-1 取り下げ（#572）で削除。生成経路が一度も無く、永続化された取引にも存在しない

data デフォルト費用区分 = 個人(夫) OR 個人(妻)
// A-1: カード所有者の個人(本人) をデフォルトに置く

data 分類根拠 = 加盟店ルール根拠 OR ユーザー手動修正根拠

data 加盟店ルール根拠 = 加盟店名 AND ルール最終更新日時
data ユーザー手動修正根拠 = ユーザーID AND 修正日時
// Amazon商品キー根拠 は X-1 取り下げで削除（#572）

// Amazon 突合の状態（取引取込の突合結果を受けて自動分類が判定する）
data Amazon突合状態 = 突合済み OR Amazon待ち OR SMBC待ち OR 突合タイムアウト確定

data 突合済み = 取引ID AND 突合確定日時
data Amazon待ち = 取引ID AND SMBC通知到着日時 AND タイムアウト期限  // SMBC 先着、Amazon 注文確認待ち
data SMBC待ち = Amazon注文ID AND Amazon到着日時 AND タイムアウト期限  // Amazon 先着、SMBC 通知待ち
data 突合タイムアウト確定 = 取引ID AND タイムアウト到達日時

// 一括分類セッション（CSV 取込・取込直後の N-1）
// aggregate root
data 一括分類セッション = ユーザーID
   AND 取込起因
   AND List<未分類取引>
   AND 一括分類状態

data 取込起因 = CSV取込起因 OR 単発修正起因 OR 取引一覧起因
data CSV取込起因 = CSV取込ID AND 開始日時
data 単発修正起因 = 取引ID AND 開始日時
data 取引一覧起因 = 開始日時  // 起点となる 1 件を持たない（未分類の一覧そのものが起点）

data 一括分類状態 = 進行中 OR 完了 OR 中断
data 進行中 = 開始日時 AND 残件数 AND List<分類済み取引ID>
// 不変条件: 分類済み取引ID は List<未分類取引> の部分集合で重複を持たない
// 不変条件: 残件数 = 対象取引数 - 分類済み取引数
data 完了 = 開始日時 AND 完了日時 AND 処理件数
data 中断 = 開始日時 AND 中断日時 AND 残件数
```

## 2. 振る舞い（behavior）

```
// 入出力 behavior。ACL 翻訳層は本コンテキストには無く、上流（取引取込）から渡された取引候補をルックアップし、
// 結果（分類済み／未分類）を下流（家計分析・経費精算）へ渡すのが基本形。

// --- ルックアップ ---

behavior 取引候補を加盟店名で分類する = 取引候補 -> 分類結果 AND 取引が自動分類で取り込まれたイベント
// 事前: 取引候補の加盟店名が NFKC 正規化済み
// 事前: 取引候補の所有者ユーザーIDが特定済み
// 事後: 加盟店学習ルールが ユーザーID AND 加盟店名 で検索された
// 事後: 学習無効化加盟店ルールに該当する場合は未分類取引として取り込まれる
// 事後: 該当ルールがあればフィールド独立で 3 軸（カテゴリ／費用区分／経費種別）を当てる

// behavior 取引候補をAmazon商品キーで分類する は X-1 取り下げで削除（#572）。
// Amazon 突合済みの取引候補も学習ルールを引かず、未分類取引として取り込む。

behavior Amazon突合タイムアウトを判定する = Amazon突合状態 AND 現在日時 -> 突合タイムアウト確定 OR 突合済み OR 待機継続
// 事前: タイムアウト期限 = 双方向 3 日
// 事後: SMBC 先着でタイムアウト確定 → 「Amazon 注文不明」フラグで未分類確定（V-2）
// 事後: Amazon 先着でタイムアウト確定 → 注文情報を破棄（配送キャンセル可能性）

data 待機継続 = 取引ID AND 残時間

// --- 学習データ更新（手動修正の反映） ---

behavior 手動修正を学習に反映する = 修正前分類 AND 修正後分類 AND ユーザーID -> 加盟店学習ルール AND 学習データが更新されたイベント
// 事前: I-1 即時反映。保存ボタン押下と同時にルールが書き換わる
// 事後: T-2 によりカテゴリ／費用区分／経費種別 のうち修正された軸のみ更新される
// 事後: F-1 により当該ユーザーIDの学習データのみ更新、配偶者の学習は変更しない

behavior 既存ルールの上書きを判定する = 修正前分類 AND 修正後分類 AND ユーザー選択 -> 加盟店学習ルール OR 既存ルール維持
// 事前: 既存ルールが存在する加盟店に対して別の値で修正された
// 事前: ユーザー選択 = 「以後このルールに従う」または「今回限り」（L-4）
// 事後: 「以後このルールに従う」→ ルール上書き、「今回限り」→ 取引のみ更新でルールは触らない

behavior 加盟店の学習を無効化する = ユーザーID AND 加盟店名 -> 学習無効化加盟店ルール AND 加盟店学習が無効化されたイベント
// 事前: 修正画面で「この加盟店は学習しない」チェックが有効化された
// 事後: 以後の取込でこの加盟店は常に未分類で取り込まれる

behavior 加盟店の学習を再有効化する = 学習無効化加盟店ルール -> 学習無効化解除 AND 加盟店学習が再有効化されたイベント

data 学習無効化解除 = ユーザーID AND 加盟店名 AND 解除日時

// --- 過去未分類への遡及（J-3） ---

behavior 過去未分類の遡及を提案する = 加盟店学習ルール AND ユーザーID -> 遡及候補リスト
// 事後: 対象は 当該ユーザーの未分類取引のみ（既分類・配偶者取引は触らない）

data 遡及候補リスト = ユーザーID AND List<取引ID> AND 提案日時

behavior 遡及一括分類を実行する = 遡及候補リスト AND ユーザー承認 -> List<分類結果> AND 過去未分類が一括再分類されたイベント OR 遡及キャンセル
// 事前: ユーザー承認 = J-3 確認ダイアログで「適用する」が選択された
// 事後: 対象取引の分類が 加盟店学習ルール の値で更新される

data 遡及キャンセル = ユーザーID AND キャンセル日時

// --- 一括分類セッション（CSV 取込時 N-1） ---

behavior 一括分類セッションを開始する = 取込起因 AND ユーザーID AND List<未分類取引> -> 一括分類セッション
// 事前: CSV取込起因 の場合は CSV 取込が完了し、新規N件／自動分類N件／未分類N件 のサマリが表示された
// 事前: 取引一覧起因 の場合は取引一覧に未分類取引が 1 件以上ある
// 事後: 同一加盟店の複数取引は 1 ルールに集約される（N-1）
// 事後: 分類済み取引ID は空、残件数 = 対象取引数

behavior 一括分類セッションを進める = 一括分類セッション AND ユーザー操作 -> 一括分類セッション AND List<加盟店学習ルール>
// 事前: 一括分類状態 = 進行中
// 事後: 同一加盟店の複数取引へのルールは 1 件に集約される
// 事後: 分類し終えた取引が 分類済み取引ID に加わり、残件数がその分だけ減る
// 事後: 記録済みの取引を再度渡しても残件数は二重に減らない（再送に対して冪等）
// 事後: とばした加盟店の取引は 分類済み取引ID に加わらない
// 事後: 分類済み取引ID に入るのは実際に分類済みになった取引だけ（申告のみでは入らない）

behavior 一括分類セッションを完了する = 一括分類セッション -> 一括分類セッション AND 一括分類完了イベント
// 事前: 一括分類状態 = 進行中
// 事後: 一括分類状態 = 完了

// --- マスタ削除リマップ（マスタ管理からの要請） ---

behavior 学習データを移動先にリマップする = 削除カテゴリID AND 移動先カテゴリID AND ユーザーID -> List<加盟店学習ルール> AND 学習データがリマップされたイベント
// 事前: マスタ管理からカテゴリ削除に伴うリマップ要請を受けた（R-2 改）
// 事後: 加盟店学習ルール のカテゴリID 参照を一括書換

behavior 経費種別の学習データを移動先にリマップする = 削除経費種別ID AND 移動先経費種別ID AND ユーザーID -> List<加盟店学習ルール> AND 学習データがリマップされたイベント
// 事前: マスタ管理から経費種別削除に伴うリマップ要請を受けた
```

## 3. ドメインイベント

```
// 本コンテキストが発火するドメインイベント。各 behavior の出力で発生主体として明示される。

data 取引が自動分類で取り込まれたイベント = 取引ID AND ユーザーID AND 分類根拠 AND 発生日時
data 取引が未分類で取り込まれたイベント = 取引ID AND ユーザーID AND 未分類理由 AND 発生日時
data 学習データが更新されたイベント = ユーザーID AND 加盟店名 AND 更新軸 AND 発生日時
data 加盟店学習が無効化されたイベント = ユーザーID AND 加盟店名 AND 発生日時
data 加盟店学習が再有効化されたイベント = ユーザーID AND 加盟店名 AND 発生日時
data 過去未分類が一括再分類されたイベント = ユーザーID AND 対象件数 AND 発生日時
data Amazon突合タイムアウトが検知されたイベント = 取引ID OR Amazon注文ID AND 発生日時
data 一括分類完了イベント = 一括分類セッションID AND 処理件数 AND 発生日時

data 更新軸 = カテゴリ軸 OR 費用区分軸 OR 経費種別軸
```

## 4. 隣接コンテキストとの境界

| 隣接 | 関係 | 翻訳層 behavior |
|---|---|---|
| 取引取込 | 顧客-供給者（上流: 取引取込が供給） | （受信側のためコンテキスト境界翻訳は取引取込側で完結。本コンテキストは取引候補を入力として受け取る） |
| 家計分析 | 顧客-供給者（下流: 家計分析が消費）／共有カーネル（取引・カテゴリ・費用区分の共通語彙） | `behavior 取引候補を加盟店名で分類する`（出力イベント経由） |
| 経費精算 | 顧客-供給者（下流: 経費精算が経費種別判定結果を消費） | 同上 behavior 群（経費種別軸の出力） |
| マスタ管理 | 顧客-供給者（上流: マスタ管理がカテゴリ／経費種別ID を供給）／要請受付 | `behavior 学習データを移動先にリマップする`／`behavior 経費種別の学習データを移動先にリマップする`（リマップ要請の受付） |
| オンボーディング・認証 | クロスコンテキスト参照（ユーザーID 借用） | （ID のみ借用。翻訳層 behavior は無し） |

# ドメイン発見 Phase 2: イベントストーミング

> このドキュメントはドメインで起きるイベント（過去形の事実）を洗い出した一次リストである。
> 粒度・重複・抽象度の混在は許容し、後段（Phase 3）で集約・コンテキスト・コマンドへ整理する。
> 凡例: 🟧 ドメインイベント / 🟦 ライフサイクル / 🟨 訂正・例外 / 🟩 資産価値 / 🟥 通知・自動処理 / 🟪 夫婦協働 / 🟫 レポート

## 1. 取引系（決済・収入・資金移動） 🟧

### 1.1 収入

- 給与が振り込まれた
- 経費精算が振り込まれた

### 1.2 支出（外部への支払い）

- クレジットカードで決済された（汎用）
- 水道光熱費がクレジットカードで支払われた
- 家賃がクレジットカードで支払われた
- 食費がクレジットカードで支払われた
- 交際費がクレジットカードで支払われた
- 趣味費がクレジットカードで支払われた
- 経費がクレジットカードで立て替えられた
- PayPayで決済された

### 1.3 資金移動（自分の口座間 / 個人間送金）

- 銀行口座からPayPayへチャージされた
- 現金からPayPayへチャージされた
- PayPayで友人に送金された
- 銀行口座からNISAへ積み立てられた
- 給与振込口座から貯蓄口座へ資金が移動された
- 貯蓄口座から振込口座へ不足分が補填された

## 2. ライフサイクル系 🟦

- 銀行口座が新規開設された
- 銀行口座が解約された
- クレジットカードが追加された
- クレジットカードが解約された
- 証券口座が開設された
- アプリが夫婦で使い始められた
- カテゴリ（費目）が新設された
- カテゴリ（費目）が廃止された
- カテゴリがまとめられた（統合された）
- 定期取引が契約された
- 定期取引が解約された

## 3. 訂正・例外系 🟨

- 取引のカテゴリが間違って分類されたため修正された
- 取引が削除された
- 二重に取り込まれた取引がマージされた
- 返金・返品でお金が戻ってきた

## 4. 資産価値変動系 🟩

- NISAの評価額が変動した

## 5. 通知・自動処理系 🟥

- 月予算の80%を超えたため警告が通知された
- 普段と違う大きな支出が検知された
- 取り込まれた取引が自動分類された
- 自動分類の精度が学習された
- 自動分類の結果が手動で修正された
- 修正結果を集約したものが学習された

## 6. 夫婦協働系 🟪

- 夫婦で目標貯蓄額が合意された
- 夫婦で目標金額が再設定された
- 大きな支出が事前承認された
- レポートが夫婦で確認された

## 7. レポート系 🟫

- 月次レポートがメールで配信された
- ダッシュボードが閲覧された
- 固定費／変動費でグルーピングされた月次集計が行われた
- 目標資産額に対する分析が実行された

## 9. Phase 2 で得られた重要な観察

イベントを並べたことで、設計上クリティカルな論点が浮かび上がった（詳細は `03-open-questions.md` を参照）。

- **「決済」と「資金移動」は別物**として扱う必要がある（混ぜると二重計上の温床）。
- **クレカ決済と銀行引落のタイミング差**を、発生主義／現金主義のどちらで扱うか方針が必要。
- **「夫婦の共有」と「個人」の区別**を、取引・口座のどのレイヤーに持たせるかを決める必要がある。
- **外部連携は「自動連携ありき」では設計できない**（日本の金融機関事情）。手入力・CSV取込もファーストクラス機能になる前提。

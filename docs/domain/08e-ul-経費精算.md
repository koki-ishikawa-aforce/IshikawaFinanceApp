# ユビキタス言語: 経費精算

> 親: [docs/domain/08-ubiquitous-language.md](./08-ubiquitous-language.md)
> サブドメイン: Core（07-bounded-contexts.md §2.2）

## 責務

経費(会社) フラグ取引の経費種別ごとの月次累計と上限管理を行い、上限超過時の先着順按分（個人(本人) への子取引分割）と、翌月15日頃の経費精算入金との突合・差額の個人費用振替・最終確定状態昇格を担う。月初リセット・按分自動再計算・無制限経費種別の扱い・最終確定後の不認定分振替を一貫した「月次経費サイクル」のライフサイクルとして管理する。

## 1. データ（data）

```
// 本コンテキストの中核は「月次経費サイクル」（集約）と「按分子取引」（取引修正で派生する子取引）。
// 月次経費サイクルは「月初リセット → 経費取引集積 → 上限按分 → 入金突合 → 最終確定」の状態遷移を持つ。

// クロスコンテキスト参照（ID のみ借用）
// referenced from: オンボーディング・認証
data ユーザーID = 文字列
// referenced from: 家計分析
data 取引ID = 文字列
// referenced from: マスタ管理
data 経費種別ID = 文字列

// 共通語彙の借用
data 金額 = 整数
data 発生日時 = 日時
data 費用区分 = 世帯 OR 個人(夫) OR 個人(妻) OR 経費(会社)

// --- 月次経費サイクル: 集約ルート ---
// 状態は OR で表現。リセット直後の空サイクルから最終確定まで遷移する。

// aggregate root
data 月次経費サイクル = 集積中サイクル OR CSV確定サイクル OR 最終確定サイクル

data 月次経費サイクル共通属性 = 月次経費サイクルID
   AND ユーザーID
   AND 対象年月
   AND サイクル開始日時
   AND List<経費種別累計>
   AND List<按分子取引参照>

data 月次経費サイクルID = 文字列

data 集積中サイクル = 月次経費サイクル共通属性
// 集積中: 月初リセット直後から CSV 取込前まで。経費取引が日々追加される

data CSV確定サイクル = 月次経費サイクル共通属性 AND CSV確定日時
// CSV確定: CSV 取込後、月次レポート CSV確定状態に対応

data 最終確定サイクル = 月次経費サイクル共通属性
   AND CSV確定日時
   AND 最終確定日時
   AND 経費精算入金参照
   AND 不認定分振替リスト

data 経費精算入金参照 = 経費精算入金ID
data 経費精算入金ID = 文字列

data 不認定分振替リスト = List<不認定分振替>
data 不認定分振替 = 元経費取引ID AND 個人費用振替先 AND 振替金額 AND 振替日時
data 個人費用振替先 = 個人(夫) OR 個人(妻)

// --- 経費種別累計 ---
// 累計は「上限あり経費種別累計」と「無制限経費種別累計」で扱いが異なる。
// is_unlimited は専用カラムで管理（論点15）し、フラグ・マジックナンバーは使わない。
// 無制限の場合は上限超過判定そのものが発生しない設計。

data 経費種別累計 = 上限あり経費種別累計 OR 無制限経費種別累計

data 上限あり経費種別累計 = 経費種別ID
   AND ユーザーID
   AND 月次上限
   AND 当月累計金額
   AND 上限到達状態
   AND List<経費取引参照>

data 月次上限 = 整数  // referenced from: マスタ管理（dependency: 月次上限の seed 値）

data 上限到達状態 = 上限未到達 OR 上限到達済み
data 上限到達済み = 到達日時 AND 到達時取引ID

data 無制限経費種別累計 = 経費種別ID
   AND ユーザーID
   AND 当月累計金額
   AND List<経費取引参照>

data 経費取引参照 = 取引ID
   AND 取引日時
   AND 取引金額
   AND 充当区分
data 充当区分 = 全額経費充当 OR 部分経費充当
data 全額経費充当 = なし
data 部分経費充当 = 経費充当金額 AND 個人充当金額 AND 子取引ID
// 部分経費充当: 上限超過時に発生。経費(会社) 部分と個人(本人) 部分に分割される。

// --- 按分子取引 ---
// 上限超過時に元取引から派生する子取引。元取引ID と関係を保つ。

// aggregate root
data 按分子取引 = 子取引ID
   AND 親取引ID
   AND ユーザーID
   AND 個人充当金額
   AND 個人費用区分
   AND 派生日時
   AND 按分根拠

data 子取引ID = 文字列
data 親取引ID = 取引ID
data 個人費用区分 = 個人(夫) OR 個人(妻)

data 按分根拠 = 上限超過先着按分 OR 経費修正再按分 OR 経費削除再按分

data 上限超過先着按分 = 月次経費サイクルID AND 按分実行日時 AND 上限超過時残額
data 経費修正再按分 = 月次経費サイクルID AND 修正起因取引ID AND 再按分日時
data 経費削除再按分 = 月次経費サイクルID AND 削除起因取引ID AND 再按分日時

data 按分子取引参照 = 子取引ID AND 親取引ID

// --- 経費取引のマーキング判定 ---
// 自動分類・学習から渡された経費種別判定を本コンテキストで受け取り、経費(会社) としてマーキングする。

data 経費判定結果 = 経費種別判定済み OR 経費種別未判定 OR 経費判定不能
data 経費種別判定済み = 取引ID AND 経費種別ID AND 判定根拠
data 経費種別未判定 = 取引ID AND 未判定理由
data 経費判定不能 = 取引ID AND 不能理由

data 判定根拠 = 加盟店ルール根拠 OR Amazon商品キー根拠 OR ユーザー手動修正根拠
data 加盟店ルール根拠 = 加盟店名 AND ルール最終更新日時
data Amazon商品キー根拠 = Amazon商品キー AND ルール最終更新日時
data ユーザー手動修正根拠 = ユーザーID AND 修正日時

data 未判定理由 = 加盟店ルール未学習 OR Amazon商品キー未学習
data 不能理由 = Amazon商品情報判定不能 OR Amazon突合タイムアウト

// --- 経費精算入金 ---

// aggregate root
data 経費精算入金 = 経費精算入金ID
   AND ユーザーID
   AND 入金金額
   AND 入金日時
   AND 突合状態

data 突合状態 = 突合待ち OR 突合済み OR 不認定分確定済み
data 突合待ち = 受信日時
data 突合済み = 突合日時 AND 突合対象月次経費サイクルID
data 不認定分確定済み = 突合日時 AND 不認定分合計 AND 振替確定日時

// --- 経費精算管理タブの可視データ（本人のみ） ---
// 対象月省略時は当月（JST 暦月）。過去月を指定するとその月のサイクルの
// 累計・按分子取引を閲覧できる（精算履歴）。直近月の最終確定サイクルは対象月に依らない。
data 経費精算管理ビュー = ユーザーID
   AND 当月経費種別累計リスト
   AND 当月按分子取引リスト
   AND 直近月の最終確定サイクル?
data 当月経費種別累計リスト = List<経費種別累計>
data 当月按分子取引リスト = List<按分子取引>
```

## 2. 振る舞い（behavior）

```
// --- 月次サイクルのライフサイクル ---

behavior 月次経費サイクルをリセットする = ユーザーID AND 対象年月 AND リセット日時 -> 集積中サイクル AND 月次経費サイクル開始イベント
// 事前: 毎月1日 0:00 のバッチ起動 または 運用開始時の初回起動
// 事後: List<経費種別累計> は空、List<按分子取引参照> は空

// --- 経費取引の取込 ---

behavior 取引を経費(会社)としてマーキングする = 取引ID AND 経費種別判定済み AND 月次経費サイクル -> 集積中サイクル AND 取引が経費としてマークされたイベント
// 事前: 自動分類・学習が経費種別判定済み を供給
// 事前: 月次経費サイクルが集積中サイクル状態
// 事後: 経費種別累計に取引が追加され、当月累計金額が更新される
// 事後: 上限あり経費種別累計が上限到達したら按分を発火する

behavior 取引を経費から外して個人費用に切り替える = 取引ID AND 切替先費用区分 AND 月次経費サイクル -> 月次経費サイクル AND 経費フラグ切替イベント AND List<按分再計算結果>
// 事前: 切替先費用区分 = 個人(本人) のいずれか
// 事後: 経費種別累計から取引を除外し、按分が自動再計算される

behavior カード利用を立替経費として手動マークする = 取引ID AND 経費種別ID AND 操作者ユーザーID -> 月次経費サイクル AND 経費フラグ切替イベント
// 事前: 操作者ユーザーID = 取引所有者ユーザーID
// 事後: 自動分類・学習に手動修正を伝搬する（学習データ更新）

// --- 上限按分（先着順） ---

behavior 経費種別累計を上限と照合する = 上限あり経費種別累計 AND 取引ID AND 取引金額 -> 充当判定 AND 経費種別累計更新イベント
// 事前: 上限あり経費種別累計
// 事後: 累計+金額 ≦ 上限 → 全額経費充当
// 事後: 累計+金額 > 上限 → 部分経費充当（上限残額のみ経費、超過分を個人(本人) に按分）

data 充当判定 = 全額充当 OR 部分充当 OR 上限超過全額個人

data 全額充当 = 取引ID AND 充当金額
data 部分充当 = 取引ID AND 経費充当金額 AND 個人充当金額 AND 派生子取引ID
data 上限超過全額個人 = 取引ID AND 個人充当金額 AND 派生子取引ID
// 累計が既に上限到達済みの場合、新規取引は全額が個人(本人) に按分される

behavior 按分子取引を派生させる = 取引ID AND 個人充当金額 AND 個人費用区分 AND 按分根拠 -> 按分子取引 AND 按分子取引派生イベント
// 事前: 個人充当金額 > 0
// 事後: 家計分析に「個人(本人) 子取引が家計分析対象に昇格」を通知する

behavior 取引修正で按分を自動再計算する = 月次経費サイクル AND 修正起因取引ID -> 月次経費サイクル AND 按分再計算イベント
// 事前: 同月内の経費取引が修正・削除・経費フラグ切替された
// 事後: 当月の経費取引を時系列順に再評価し、按分子取引リストが再生成される

// --- 経費精算入金との突合 ---

behavior 経費精算入金を受信する = 経費精算入金到着イベント -> 経費精算入金 AND 経費精算入金受信イベント
// 事前: 残高・資産推移管理が「経費精算入金到着イベント」を発火した（用途判別結果 = 経費精算入金判別）
// 事後: 突合状態 = 突合待ち

behavior 経費精算入金と当月経費を突合する = 経費精算入金 AND CSV確定サイクル -> 経費精算入金 AND 経費突合イベント
// 事前: 経費精算入金の入金日時の前月分が CSV確定サイクル
// 事後: 突合状態 = 突合済み、当月経費合計と入金金額の差額が算出される

behavior 不認定分を個人費用に振り替える = 経費精算入金 AND CSV確定サイクル AND 突合差額 -> 最終確定サイクル AND 経費突合差額振替イベント
// 事前: 突合状態 = 突合済み
// 事後: 不認定分が「個人(本人)」費用に振り替えられる
// 事後: 月次経費サイクルが最終確定サイクル状態に遷移し、家計分析に「経費精算サイクル確定」を通知する

data 突合差額 = 不認定分 OR 認定済み超過 OR 完全一致
data 不認定分 = 差額金額  // 入金額 < 暫定経費合計
data 認定済み超過 = 差額金額  // 入金額 > 暫定経費合計（社内処理上の調整等、稀ケース）
data 完全一致 = なし

// --- 月次レポートの最終確定昇格を通知 ---

behavior 月次経費精算サイクルを確定する = 最終確定サイクル -> 月次経費精算サイクル確定イベント
// 事前: 不認定分振替リストが確定済み
// 事後: 家計分析に「月次レポートを最終確定状態に昇格する」依頼を発火

// --- 経費精算管理タブ ---

behavior 経費精算管理ビューを構築する = ユーザーID AND 閲覧者 AND 対象年月? -> 経費精算管理ビュー OR 配偶者からのアクセス拒否
// 事前: 閲覧者ユーザーID = ユーザーID（本人のみ可視、論点11 + プライバシールール3段階）
// 対象年月省略時は当月（JST 暦月）。過去月指定でその月の精算履歴を閲覧する

data 配偶者からのアクセス拒否 = 拒否日時 AND 拒否理由

// --- マスタ削除リマップ受付 ---

behavior 経費種別削除に伴う取引の経費種別移動を反映する = 削除経費種別ID AND 移動先経費種別ID AND 移動先費用区分 -> List<経費取引参照> AND 経費種別移動イベント
// 事前: マスタ管理から経費種別削除リマップ要請を受けた
// 事後: 配下取引の経費種別ID と必要に応じて費用区分が更新され、当月按分が再計算される
```

## 3. ドメインイベント

```
data 月次経費サイクル開始イベント = 月次経費サイクルID AND ユーザーID AND 対象年月 AND 発生日時
data 取引が経費としてマークされたイベント = 取引ID AND 経費種別ID AND ユーザーID AND 発生日時
data 経費フラグ切替イベント = 取引ID AND 旧費用区分 AND 新費用区分 AND 操作者ユーザーID AND 発生日時
data 経費種別累計更新イベント = 経費種別累計ID AND 当月累計金額 AND 上限到達状態 AND 発生日時
data 経費種別累計ID = 文字列
data 按分子取引派生イベント = 子取引ID AND 親取引ID AND 個人充当金額 AND 按分根拠 AND 発生日時
data 按分再計算イベント = 月次経費サイクルID AND 修正起因取引ID AND 再計算後子取引数 AND 発生日時
data 経費精算入金受信イベント = 経費精算入金ID AND 入金金額 AND 発生日時
data 経費突合イベント = 経費精算入金ID AND 月次経費サイクルID AND 突合差額 AND 発生日時
data 経費突合差額振替イベント = 月次経費サイクルID AND 不認定分合計 AND List<個人費用振替先> AND 発生日時
data 月次経費精算サイクル確定イベント = 月次経費サイクルID AND 最終確定日時 AND 発生日時
data 経費種別移動イベント = 旧経費種別ID AND 新経費種別ID AND 影響取引数 AND 発生日時
```

## 4. 隣接コンテキストとの境界

| 隣接 | 関係 | 翻訳層 behavior |
|---|---|---|
| 自動分類・学習 | 顧客-供給者（上流: 経費種別判定結果を供給） | （受信側のため翻訳層は自動分類側。本コンテキストは `behavior 取引を経費(会社)としてマーキングする` で取り込み） |
| 残高・資産推移管理 | 顧客-供給者（上流: 経費精算入金到着イベントを供給） | `behavior 経費精算入金を受信する`（経費精算入金到着イベントの受付） |
| 家計分析 | 顧客-供給者（双方向: 按分子取引の家計昇格／最終確定への昇格依頼／経費フラグ切替の通知） | `behavior 按分子取引を派生させる`／`behavior 月次経費精算サイクルを確定する`（最終確定の依頼）／`behavior 取引を経費から外して個人費用に切り替える` |
| マスタ管理 | 顧客-供給者（上流: 経費種別マスタ・月次上限の参照／削除リマップ要請の受付） | `behavior 経費種別削除に伴う取引の経費種別移動を反映する`（リマップ要請の受付） |
| オンボーディング・認証 | クロスコンテキスト参照（ユーザーID 借用） | （ID のみ借用。翻訳層 behavior は無し） |

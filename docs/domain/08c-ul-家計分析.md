# ユビキタス言語: 家計分析

> 親: [docs/domain/08-ubiquitous-language.md](./08-ubiquitous-language.md)
> サブドメイン: Core（07-bounded-contexts.md §2.2）
> 改訂（2026-07-24・判断セッション / #108）: 閲覧者本人を基準に相対化した費用区分別合計を指す用語「本人視点合計」を追加（§1 の当月費用区分別合計を参照）。

## 責務

分類済み取引を費用区分（世帯／個人(夫)／個人(妻)／経費(会社)）とカテゴリで集計し、ダッシュボードのリアルタイム表示と月次レポートの 2 状態（CSV確定／最終確定）の生成を担う。プライバシールール 3 段階（世帯フルオープン／個人は合計のみ相手可視／経費(会社) は本人のみ可視）を表示時に適用する。経費(会社) は集計から除外する非対称ルールを守り、CSV 取込時の差額確定（暫定→確定切替）と最終確定での不認定分振替の取込を行う。

## 1. データ（data）

```
// 本コンテキストの中核は「取引（集約ルート）」と「月次レポート」の 2 つ。
// 取引は自動分類・学習から渡された分類結果をもとに本コンテキストで永続化・参照される。
// 月次レポートは状態遷移を持つ。

// クロスコンテキスト参照（ID のみ借用）
// referenced from: オンボーディング・認証
data ユーザーID = 文字列  // LINE userID
// referenced from: マスタ管理
data カテゴリID = 文字列
data 経費種別ID = 文字列
// referenced from: 残高・資産推移管理
data 口座ID = 文字列

// 共通語彙の借用
data 取引ID = 文字列  // ULID
data 加盟店名 = 文字列
data 金額 = 整数
data 発生日時 = 日時
data 費用区分 = 世帯 OR 個人(夫) OR 個人(妻) OR 経費(会社)
data 所有者 = 夫 OR 妻 OR 共有

// 取引: 集約ルート
// 取引のライフサイクルは「未分類で取り込まれる → 分類済みになる → 削除／マージ／返金」の遷移を持つ。
// フラグ・ステータスコードは使わず、状態を OR で表現する。

// aggregate root
data 取引 = 未分類取引 OR 分類済み取引 OR 削除済み取引

data 共通取引属性 = 取引ID
   AND 所有者ユーザーID
   AND 加盟店名
   AND 金額
   AND 発生日時
   AND 取込ソース

data 取込ソース = メール由来 OR CSV由来 OR PDF由来 OR Amazon突合由来 OR 手動入力由来 OR CSV手動マージ由来
data メール由来 = Gmail_message_ID
data CSV由来 = CSVファイルID AND 行番号
data PDF由来 = PDFファイルID AND ページ番号
data Amazon突合由来 = SMBC_Gmail_message_ID AND Amazon注文ID
data 手動入力由来 = 入力日時 AND 入力者ユーザーID
data CSV手動マージ由来 = 元取引ID AND マージ日時

data 未分類取引 = 共通取引属性
   AND 未分類理由
   AND デフォルト費用区分
// referenced from: 自動分類・学習（未分類理由・デフォルト費用区分の値は同義）
data 未分類理由 = 加盟店ルール未学習 OR Amazon商品キー未学習 OR Amazon商品情報判定不能 OR Amazon突合タイムアウト OR 学習無効化適用
data デフォルト費用区分 = 個人(夫) OR 個人(妻)

data 分類済み取引 = 共通取引属性
   AND カテゴリID
   AND 費用区分
   AND 経費種別参照
   AND 分類根拠

data 経費種別参照 = 経費(会社)取引 OR 非経費取引
data 経費(会社)取引 = 経費種別ID
// 経費(会社) のとき経費種別が必須。それ以外では経費種別を持たない。
// これにより「経費(会社) 切替時に経費種別未指定」という業務上ありえない状態を許容しない。
data 非経費取引 = なし

data 分類根拠 = 加盟店ルール根拠 OR Amazon商品キー根拠 OR ユーザー手動修正根拠 OR CSV取込時一括分類根拠
data 加盟店ルール根拠 = 加盟店名 AND ルール最終更新日時
data Amazon商品キー根拠 = Amazon商品キー AND ルール最終更新日時
data ユーザー手動修正根拠 = 修正者ユーザーID AND 修正日時
data CSV取込時一括分類根拠 = 一括分類セッションID AND 適用日時

data 削除済み取引 = 共通取引属性 AND 削除日時 AND 削除理由
data 削除理由 = ユーザー削除 OR 二重取込マージ吸収 OR 返金マッチ吸収

// 返金取引（カード返金通知メール経由 or 手動）
data 返金取引 = 共通取引属性 AND 元取引参照?
data 元取引参照 = 取引ID AND 突合日時  // 元取引が特定できた場合のみ

// 二重取込のマージ
data マージ取引 = 取引ID AND List<元取引ID> AND マージ日時 AND マージ確定者ユーザーID

// プライバシールール（表示時に適用）
data プライバシースコープ = 世帯フルオープン OR 個人合計のみ可視 OR 本人のみ可視
// 世帯フルオープン: 費用区分 = 世帯 の取引明細・合計が両者に見える
// 個人合計のみ可視: 費用区分 = 個人(本人) は本人に明細・合計、配偶者には合計のみ
// 本人のみ可視: 費用区分 = 経費(会社) は本人のみ、配偶者には合計すら見えない

behavior_input data 閲覧者 = ユーザーID AND 閲覧者役割
data 閲覧者役割 = 本人 OR 配偶者

// 月次レポート: 集約ルート
// 状態は OR で表現。CSV確定 と 最終確定 の 2 状態。

// aggregate root
data 月次レポート = CSV確定月次レポート OR 最終確定月次レポート

data 月次レポート共通属性 = 月次レポートID
   AND 対象年月
   AND 世帯費用カテゴリ別合計
   AND 個人費用合計(夫)
   AND 個人費用合計(妻)
   AND 経費(会社)合計(夫)
   AND 経費(会社)合計(妻)
   AND NISA積立累計
   AND 残高推移パート
   AND 不完全月フラグ?
// 不完全月フラグ?: 運用開始月のレポートのみ付与。? は業務上の任意性として許容（論点20）

data 不完全月フラグ = 運用開始月レポート

data CSV確定月次レポート = 月次レポート共通属性
   AND CSV確定日時
   AND CSV確定起因取引リスト

data CSV確定起因取引リスト = List<取引ID>

data 最終確定月次レポート = 月次レポート共通属性
   AND CSV確定日時
   AND 最終確定日時
   AND 経費精算入金参照
   AND 不認定分振替リスト
data 経費精算入金参照 = 経費精算入金ID AND 突合日時  // referenced from: 経費精算
data 不認定分振替リスト = List<不認定分振替>
data 不認定分振替 = 元経費取引ID AND 個人費用振替先 AND 振替金額 AND 振替日時
data 個人費用振替先 = 費用区分  // 個人(夫) または 個人(妻) のみ取りうる

data 残高推移パート = SMBC残高推移 AND 別銀行貯蓄残高推移 AND NISA積立累計推移 AND 三井住友カード未払金推移
// referenced from: 残高・資産推移管理

// ダッシュボード集計（リアルタイム）
data ダッシュボード集計 = ユーザーID
   AND 対象年月
   AND 当月費用区分別合計
   AND 当月カテゴリ別合計
   AND 未分類サマリ
   AND 残高鮮度評価リスト

data 当月費用区分別合計 = 世帯合計 AND 個人合計(本人) AND 個人合計(配偶者) AND 経費(会社)合計(本人)?
// 経費(会社)合計(本人) は本人閲覧時のみ含まれる（プライバシー）
// 本人視点合計: 上記の「(本人)」「(配偶者)」は役割固定（Honey/Darling）ではなく、閲覧者本人を基準に相対化した合計を指す。
//   閲覧者が誰であっても「本人」= その閲覧者自身、「配偶者」= 相手を表す。
//   コード上は businessExpenseTotalSelf 等の `...Self` サフィックス（本人視点への読み替え。旧称「本人(Self)射影」）で表現する。

data 当月カテゴリ別合計 = List<カテゴリ別小計>
data カテゴリ別小計 = カテゴリID AND 金額 AND 件数

data 未分類サマリ = ユーザーID AND 件数 AND 直近未分類取引リスト
data 直近未分類取引リスト = List<取引ID>

// 残高鮮度評価（鮮度判定は家計分析、最終更新日時は残高・資産推移管理から借用）
data 残高鮮度評価リスト = List<残高鮮度評価>
data 残高鮮度評価 = 口座ID AND 最終更新日時 AND 経過日数 AND 鮮度状態
data 鮮度状態 = 鮮度OK OR 鮮度アラート
// referenced from: 残高・資産推移管理（最終更新日時は借用、評価ロジックは本コンテキスト）

// 差額検出と暫定計上（CSV 取込前の差額一時計上）
data 差額暫定計上 = 月次レポートID AND 暫定差額金額 AND 「不明（その他）」カテゴリID AND 計上日時 AND 暫定状態
data 暫定状態 = 暫定 OR 確定済み
// 「暫定」は CSV 取込前。CSV 取込で差額が確定したら 確定済み に遷移する
```

## 2. 振る舞い（behavior）

```
// --- 取引のライフサイクル ---

behavior 未分類取引を取り込む = 取引候補 AND 未分類理由 -> 未分類取引 AND 取引が未分類で取り込まれたイベント
// 事前: 取引候補が自動分類・学習からルックアップ未学習として渡された
// 事後: デフォルト費用区分 = カード所有者の個人(本人)（A-1）

behavior 自動分類済み取引を取り込む = 取引候補 AND 分類結果 -> 分類済み取引 AND 取引が自動分類で取り込まれたイベント
// 事前: 自動分類・学習が分類結果を確定させた
// 事後: 経費(会社) なら経費種別必須

behavior 取引のカテゴリを手動修正する = 分類済み取引 AND 新カテゴリID AND 修正者ユーザーID -> 分類済み取引 AND カテゴリ手動修正イベント
// 事前: 修正者ユーザーID = 取引の所有者ユーザーID
// 事後: 自動分類・学習に手動修正を伝搬し、加盟店学習ルールが更新される

behavior 取引の費用区分を手動修正する = 分類済み取引 AND 新費用区分 AND 修正者ユーザーID -> 分類済み取引 AND 費用区分手動修正イベント
// 事前: 修正者ユーザーID = 取引の所有者ユーザーID
// 事後: 経費(会社) → 非経費 OR 非経費 → 経費(会社) の場合、経費精算へ伝搬する

behavior 未分類取引を分類して確定する = 未分類取引 AND ユーザー入力分類 -> 分類済み取引 AND 取引が手動分類確定したイベント
// 事前: ユーザー入力分類がカテゴリ／費用区分の両軸を含む
// 事後: 学習データに反映される（自動分類・学習に伝搬）

behavior 取引を削除する = 取引 AND 削除者ユーザーID -> 削除済み取引 AND 取引削除イベント
// 事前: 削除者ユーザーID = 取引の所有者ユーザーID
// 事後: 残高・資産推移管理に削除を通知し、残高・未払金が再計算される
// 事後: 経費(会社) 取引なら経費精算に削除を通知し、按分が再計算される

behavior 二重取込取引をマージする = List<取引> AND マージ確定者ユーザーID -> マージ取引 AND 取引マージイベント
// 事前: 全取引の所有者ユーザーID = マージ確定者ユーザーID
// 事後: 元取引は削除済みフラグではなく削除済み取引状態に遷移する

behavior 返金取引を取り込む = 返金通知 OR 手動入力 -> 返金取引 AND 返金取込イベント
// 事後: 元取引参照は突合できた場合のみ付与される

// --- ダッシュボード集計（リアルタイム） ---

behavior ダッシュボード集計を構築する = ユーザーID AND 対象年月 AND 閲覧者 -> ダッシュボード集計 OR 月次レポート画面封印
// 事前: 閲覧者役割が決定済み（オンボーディング・認証から提供）
// 事後: プライバシールールが適用され、配偶者の経費(会社)合計は除外される
// 事後: 運用開始前は 月次レポート画面封印 を返す（論点18）

data 月次レポート画面封印 = 「準備中」表示 AND 配偶者完了待ち状態

// --- 月次レポートの状態遷移 ---

behavior 月次レポートをCSV確定状態に昇格する = 月次レポート共通属性 AND 起因CSV取込ID -> CSV確定月次レポート AND 月次レポートCSV確定イベント
// 事前: CSV 取込・分析が完了した（取引取込から CSV 取込完了通知を受信）
// 事後: 通知配信に LINE 配信トリガーを発火する

behavior 月次レポートを最終確定状態に昇格する = CSV確定月次レポート AND 経費精算入金参照 AND 不認定分振替リスト -> 最終確定月次レポート AND 月次レポート最終確定イベント
// 事前: 経費精算から「経費精算サイクル確定」通知を受信
// 事後: LINE 配信は行わない（OQ-22）。値のみ更新で差分は次月レポートで吸収

// --- 差額検出・暫定計上 ---

behavior 引落確定通知の差額を検出する = カード引落確定通知 AND 当月利用通知合計 -> 差額暫定計上 AND 差額検出イベント
// 事前: 引落確定通知メールが取引取込から渡された
// 事後: 差額が「不明（その他）」として暫定計上される

behavior CSV取込で差額を確定する = 差額暫定計上 AND CSV取込結果 -> 差額暫定計上 AND 月次レポート暫定差額確定イベント
// 事前: 暫定状態 = 暫定
// 事後: 暫定状態 = 確定済み に遷移し、月次レポートが「暫定」→「確定」に切り替わる

// --- 取引一覧と未分類修正動線 ---

behavior 未分類取引一覧を表示する = ユーザーID AND 閲覧者 -> List<未分類取引>
// 事後: 表示対象は本人の未分類取引のみ（F-1 個人別）

behavior 取引修正画面を開く = 取引ID AND 閲覧者 -> 取引修正画面起動 OR 権限エラー
// 事前: 閲覧者役割 = 本人

data 取引修正画面起動 = 取引ID AND 開始日時
data 権限エラー = 拒否理由 AND 拒否日時
data 拒否理由 = 配偶者の取引へのアクセス拒否 OR 役割未確定

// --- 残高鮮度評価 ---

behavior 残高鮮度を評価する = 口座ID AND 最終更新日時 AND 現在日時 -> 残高鮮度評価
// 事前: 口座ID と 最終更新日時 は残高・資産推移管理から借用
// 事後: 経過日数が閾値以上なら 鮮度状態 = 鮮度アラート、月次レポート画面で表示色を切り替える
// 閾値 = 35 日（OQ-44、2026-07-24 確定）。対象は別銀行貯蓄口座の手入力残高のみ。
//   通知先は画面表示のみで LINE 配信は行わない

// --- マスタ削除リマップ受付 ---

behavior カテゴリ削除に伴う取引のカテゴリ移動を反映する = 削除カテゴリID AND 移動先カテゴリID AND 移動先費用区分 -> List<分類済み取引> AND 取引のカテゴリ移動イベント
// 事前: マスタ管理からカテゴリ削除リマップ要請を受けた（Q-2 改）
// 事後: 配下取引のカテゴリID と必要に応じて費用区分が更新される
```

## 4. 隣接コンテキストとの境界

| 隣接 | 関係 | 翻訳層 behavior |
|---|---|---|

# ユビキタス言語: 通知配信

> 親: [docs/domain/08-ubiquitous-language.md](./08-ubiquitous-language.md)
> サブドメイン: Generic（07-bounded-contexts.md §2.2）

## 責務

LINE 共通トークルーム／個人 DM への push（CSV 取込リマインダー・月次レポートサマリ・OAuth 失効通知・テスト送信）と、LINE 連続失敗時のフェイルセーフメール送信、および配信時点の値の凍結用途の LINE 配信ログ保存（送信 payload を json で保持）を担う。LINE Messaging API のラッパーであり独自の判断ロジックは持たない（送信先 ID・ペイロードは他コンテキストが決定）。LINE 関連のセットアップ（友達追加・招待・Webhook 受信）はオンボーディング・認証側に帰属する（§1.1.5 確定）。

## 1. データ（data）

```
// 本コンテキストの中核は「配信メッセージ」（集約）と「LINE 配信ログ」「フェイルセーフメール」。
// LINE Messaging API への送信を ACL として包む。

// クロスコンテキスト参照（ID のみ借用）
// referenced from: オンボーディング・認証
data ユーザーID = 文字列  // = LINE_userID
data 共通トークルームID = 文字列
data 有効化日時 = 日時  // 世帯通知有効化記録の確定に使う（テスト送信イベント、#590）
// referenced from: マスタ管理
data Channel_Access_Token保管参照 = Parameter_Store_path
data Parameter_Store_path = 文字列
// referenced from: 家計分析
data 月次レポートID = 文字列
// referenced from: 取引取込
data 取込ジョブID = 文字列

// 共通語彙の借用
data 発生日時 = 日時

// --- 配信メッセージ: 集約ルート ---
// 配信先・形式・内容を保持し、送信ライフサイクルを持つ。

// aggregate root
data 配信メッセージ = 送信予約済みメッセージ OR 送信中メッセージ OR 送信成功メッセージ OR 送信失敗メッセージ OR 送信スキップメッセージ

data 配信メッセージ共通属性 = 配信メッセージID
   AND 配信先
   AND 配信内容
   AND 配信用途

data 配信メッセージID = 文字列

data 配信先 = 共通トークルーム配信先 OR 個人DM配信先
data 共通トークルーム配信先 = 共通トークルームID
data 個人DM配信先 = ユーザーID

data 配信内容 = プレーンテキスト配信内容 OR Flex_Message配信内容

data プレーンテキスト配信内容 = テキスト本文 AND リンクURL?
data テキスト本文 = 文字列
data リンクURL = 文字列

data Flex_Message配信内容 = Flex_payload AND リンクURL
data Flex_payload = json文字列

data 配信用途 = CSV取込リマインダー OR 月次レポートサマリ世帯部分 OR 月次レポート個人サマリ OR OAuth失効通知 OR テストメッセージ

// 状態の場合分け
data 送信予約済みメッセージ = 配信メッセージ共通属性 AND 予約日時
data 送信中メッセージ = 配信メッセージ共通属性 AND 送信開始日時
data 送信成功メッセージ = 配信メッセージ共通属性 AND 送信完了日時 AND LINE_message_ID参照
data 送信失敗メッセージ = 配信メッセージ共通属性 AND 送信失敗日時 AND 送信失敗理由 AND リトライ状態

data LINE_message_ID参照 = 文字列
data 送信失敗理由 = LINE_API_失敗 OR タイムアウト失敗 OR 配信先不正
data リトライ状態 = リトライ予定 OR リトライ放棄
// 粒度に注意: リトライ状態は「この配信メッセージを再試行するか」で、送信失敗は常に
// リトライ放棄（メッセージ単位の再試行基盤は無い、論点23）。一方 LINE配信ログ側の
// 配信確定は「この冪等性キーの配信をそれ以上試みるか」で、未確定なら次の機会に
// **新しい配信メッセージ**として送り直される（#441-A）。両者は矛盾しない。

data 送信スキップメッセージ = 配信メッセージ共通属性 AND スキップ日時 AND スキップ理由
data スキップ理由 = リマインダー停止条件成立 OR 通知機能無効化中 OR 配信先未確定

// --- LINE 配信ログ: 集約ルート ---
// シナリオC で確定した「スナップショット廃止の代替」。送信 payload を json で永続化し、
// 配信時点の値の凍結を担う（OQ-34）。

// aggregate root
data LINE配信ログ = 配信ログID
   AND 配信メッセージID
   AND 配信タイミング種別
   AND 配信先
   AND 送信payload_json
   AND 送信結果ステータス
   AND 送信日時
   AND 冪等性キー

data 配信ログID = 文字列
data 配信タイミング種別 = リマインダータイミング OR CSV確定昇格タイミング OR OAuth失効検知タイミング OR テスト送信タイミング
data 送信payload_json = json文字列  // 送信 payload をそのまま保存
data 送信結果ステータス = 成功 OR 失敗 OR スキップ
data 冪等性キー = 文字列  // 同月レポート再送信の重複検知

// 配信確定 = その冪等性キーの配信をそれ以上試みない、と決まった状態（#441-A）。
// 「配信先が確定済み」「CSV確定昇格」の"確定"とは別の語なので取り違えないこと。
data 配信確定判定 = 配信確定 OR 配信未確定
data 配信確定 = 成功 OR スキップ OR 未達が確定していない失敗
data 配信未確定 = 未達が確定した失敗  // = LINE_API_失敗（LINE がエラーを返した / 接続できなかった）
// 再送信してよいのは「LINE に届いていないと断定できる失敗」だけに絞る:
//  - LINE_API_失敗 → 未達が確定。次の機会（CSV の再取込・同日中の再実行など）に再送信する
//  - タイムアウト失敗 → こちらが待つのをやめただけで LINE 側は受理済みかもしれない。
//    再送信すると金額入りの月次サマリが 2 通届きうるため、従来どおり確定扱いにする
//  - 配信先不正 → 時間が経っても直らない。何度送っても同じ失敗を繰り返すだけなので確定扱い
// 月次レポートサマリは月に 1 通しか送る機会が無く、1 回の失敗で永久に届かなくなるのを防ぐのが目的。
// 同一冪等性キーには未確定の失敗ログが複数件並び、確定ログは高々 1 件だけ積まれる。
// 判定の正はドメイン関数 concludesDelivery / concludedDeliveryOf（DB の partial unique index は最終保証）。

data 成功 = LINE_message_ID参照 AND 送信完了日時
data 失敗 = 送信失敗理由 AND 送信失敗日時
data スキップ = スキップ理由 AND スキップ日時

// --- 連続失敗カウンタ ---

data 連続失敗カウンタ = ユーザーID OR 共通トークルームID
   AND 連続失敗回数
   AND 最終失敗日時
   AND しきい値到達状態

data しきい値到達状態 = しきい値未到達 OR しきい値到達済み
data しきい値到達済み = 到達日時 AND フェイルセーフ発火状態

data フェイルセーフ発火状態 = 未発火 OR フェイルセーフ発火済み
data フェイルセーフ発火済み = 発火日時 AND フェイルセーフメールID

// --- フェイルセーフメール: 集約ルート ---

// aggregate root
data フェイルセーフメール = 送信予約済みメール OR 送信中メール OR 送信成功メール OR 送信失敗メール

data フェイルセーフメール共通属性 = フェイルセーフメールID
   AND 宛先メールアドレス
   AND 件名
   AND メール本文
   AND 起因連続失敗カウンタ参照

data フェイルセーフメールID = 文字列
data 宛先メールアドレス = 文字列  // 夫婦各自の登録メールアドレス
data 件名 = 文字列
data メール本文 = 文字列
data 起因連続失敗カウンタ参照 = ユーザーID OR 共通トークルームID

data 送信予約済みメール = フェイルセーフメール共通属性 AND 予約日時
data 送信中メール = フェイルセーフメール共通属性 AND 送信開始日時
data 送信成功メール = フェイルセーフメール共通属性 AND 送信完了日時 AND メール送信プロバイダ参照
data 送信失敗メール = フェイルセーフメール共通属性 AND 送信失敗日時 AND メール送信失敗理由

data メール送信プロバイダ参照 = 文字列
data メール送信失敗理由 = SMTP失敗 OR SES失敗 OR タイムアウト失敗

// --- リマインダー停止判定の入力 ---

data CSV取込完了状態 = ユーザーID AND 対象月 AND 完了日時
// referenced from: 取引取込（取込状態を参照）
```

## 2. 振る舞い（behavior）

```
// --- ACL 翻訳層: 内部表現 → LINE Messaging API ---

behavior LINE push API を呼び出す = 配信メッセージ AND Channel_Access_Token保管参照 -> 送信成功メッセージ OR 送信失敗メッセージ AND LINE配信ログ
// 事前: Channel Access Token がマスタ管理から取得可能
// 事前: 配信先（共通トークルームID または ユーザーID）が確定済み
// 事後: 成功なら LINE_message_ID を保存、失敗なら連続失敗カウンタを更新
// 事後: 送信 payload を LINE 配信ログに保存

behavior LINE 配信ログを保存する = 配信メッセージ AND 送信結果ステータス AND 送信payload_json -> LINE配信ログ AND 配信ログ保存イベント
// 事前: 冪等性キーが計算済み（同月レポート再送信の重複検知用）
// 事前: 同一冪等性キーの配信が 配信確定 になっていない（§1 の配信確定判定）
// 事後: payload を json で永続化（OQ-34）
// 事後: 配信未確定の失敗ログは、同一冪等性キーの次の配信機会で再送信される（#441-A）
// 事後: 再送信の 1 回は連続失敗カウンタの 1 回として数える（送信試行ごとに数えるため、
//       障害が続けばフェイルセーフメールのしきい値に早く到達する）

// --- リマインダー配信 ---

behavior CSV取込リマインダーを送信する = 共通トークルームID AND 当月 AND CSV取込完了状態 -> 配信メッセージ AND リマインダー送信イベント OR リマインダー停止
// 事前: 当月 5 日以降、CSV 取込が未完了（取引取込から状態参照）
// 事後: プレーンテキスト形式で SMBC 明細ダウンロード URL ＋ アプリアップロード画面 URL を含める（OQ-12）
// 事後: CSV 取込完了状態が成立していたら リマインダー停止 を返す

data リマインダー停止 = 共通トークルームID AND 当月 AND 停止日時

behavior リマインダーの停止を判定する = ユーザーID AND 当月 -> リマインダー継続判定
data リマインダー継続判定 = 継続 OR 停止
data 継続 = 判定日時
data 停止 = 判定日時 AND 停止理由
data 停止理由 = CSV取込完了 OR 通知機能無効化中

// --- 月次レポートサマリ配信 ---

behavior 月次レポートサマリを共通トークルームに配信する = 月次レポートID AND 共通トークルームID -> 配信メッセージ AND 月次レポート世帯サマリ配信イベント
// 事前: 家計分析が「月次レポートCSV確定イベント」を発火
// 事後: Flex Message リッチカード形式で世帯費用カテゴリ別 + NISA積立累計 + 残高推移 を配信（OQ-12）
// 事後: 不完全月のレポートは金額より前に注意書きを添える（#442。レポート画面の注意と同じ条件）
// 事後: 配信時点の payload を LINE 配信ログに保存（スナップショット代替、OQ-34）

behavior 月次レポート個人サマリを個人DMに配信する = 月次レポートID AND ユーザーID -> 配信メッセージ AND 月次レポート個人サマリ配信イベント
// 事前: 同上の月次レポートCSV確定イベント
// 事後: 個人費用合計 ＋ 経費(会社) 合計 を Flex Message リッチカード形式で本人 DM に配信（プライバシー）
// 事後: 不完全月の注意書きは世帯サマリと同じ条件で添える（#442）

// --- OAuth 失効通知 ---

behavior OAuth失効通知を個人DMに配信する = ユーザーID AND Gmail_OAuth失効検知 -> 配信メッセージ AND OAuth失効通知配信イベント
// 事前: 取引取込から OAuth 失効検知通知（オンボーディング・認証経由）を受信
// 事後: 失効した本人にのみ LINE 個人 DM で通知（OQ-2）
// 事後: メールフェイルセーフ対象外
// 注記: 「配信メッセージを送信する」の一般事前条件「通知機能が有効化済み」はこの behavior には
//       適用しない（#392）。再認可されるまで自動取込が止まり続ける復旧の唯一の呼びかけであり、
//       有効化前でも本人 DM に届ける（月次サマリ・テストメッセージとの意図的な違い）

data Gmail_OAuth失効検知 = ユーザーID AND 検知日時

// --- テストメッセージ送信 ---

behavior テストメッセージを送信する = 共通トークルームID AND 運用開始確定 -> 配信メッセージ AND テスト送信イベント
// 事前: オンボーディング・認証の Phase 4 で `通知機能を有効化する` から呼出
// 事後: 配信成功で運用開始の最終確認
// 事後: テスト送信イベント は配信確定（成功 or 冪等性キーが既に確定済みでのスキップ）のたびに
//       発行する。オンボーディング・認証の 世帯通知有効化記録（08f §1）は本イベントを検知して
//       初めて書くため（#590）、確定を伝え直さないと記録が永久に欠けたままになりうる。
//       実際の LINE 送信は冪等性キーで 1 回に絞られるため、再発行そのものは実害にならない

data 運用開始確定 = 夫ユーザーID AND 妻ユーザーID AND 運用開始日時

// --- 単発失敗・連続失敗の扱い ---

behavior 単発送信失敗を記録する = 送信失敗メッセージ -> 連続失敗カウンタ AND 単発失敗ログイベント
// 事前: 単発失敗は完全スキップ（ログのみ、論点23）
// 事後: ログ + 連続失敗カウンタ +1

behavior 連続失敗をしきい値で判定する = 連続失敗カウンタ -> しきい値到達状態 AND しきい値到達イベント?
// 事後: しきい値到達ならフェイルセーフメール送信を発火（OQ-14）

// --- フェイルセーフメール送信 ---

behavior フェイルセーフメールを送信する = しきい値到達済み AND 宛先メールアドレス -> フェイルセーフメール AND フェイルセーフメール送信イベント OR フェイルセーフ送信失敗イベント
// 事前: 連続失敗しきい値到達済み
// 事後: SMTP / SES 等の標準送信プロバイダで送信（OQ-14、独自ロジック持たない）

// --- 配信メッセージのライフサイクル管理 ---

behavior 配信メッセージを予約する = 配信先 AND 配信内容 AND 配信用途 -> 送信予約済みメッセージ
// 事前: 配信先が確定済み（オンボーディング・認証の状態に依存）

behavior 配信メッセージを送信する = 送信予約済みメッセージ -> 送信成功メッセージ OR 送信失敗メッセージ OR 送信スキップメッセージ
// 事前: 通知機能が有効化済み

// --- 設定値参照 ---

behavior LINE Channel設定値を取得する = ユーザーID -> Channel_Access_Token保管参照
// 事前: マスタ管理が Phase 0 で投入済み
// 事後: Parameter Store から復号して使用
```

## 3. ドメインイベント

```
data 配信ログ保存イベント = 配信ログID AND 配信メッセージID AND 送信結果ステータス AND 発生日時
data リマインダー送信イベント = 配信メッセージID AND 共通トークルームID AND 対象月 AND 発生日時
data リマインダー停止イベント = 共通トークルームID AND 対象月 AND 停止理由 AND 発生日時
data 月次レポート世帯サマリ配信イベント = 配信メッセージID AND 月次レポートID AND 共通トークルームID AND 発生日時
data 月次レポート個人サマリ配信イベント = 配信メッセージID AND 月次レポートID AND ユーザーID AND 発生日時
data OAuth失効通知配信イベント = 配信メッセージID AND ユーザーID AND 発生日時
data テスト送信イベント = 配信メッセージID AND 共通トークルームID AND 有効化日時 AND 発生日時
// 有効化日時 はオンボーディング・認証からの借用（referenced from: オンボーディング・認証）。
// 世帯通知有効化記録（08f §1）を配信確定のタイミングで書くための入力（#590）
data 単発失敗ログイベント = 配信メッセージID AND 送信失敗理由 AND 発生日時
data しきい値到達イベント = 連続失敗カウンタ参照 AND 連続失敗回数 AND 発生日時
data フェイルセーフメール送信イベント = フェイルセーフメールID AND 宛先メールアドレス AND 発生日時
data フェイルセーフ送信失敗イベント = フェイルセーフメールID AND メール送信失敗理由 AND 発生日時

data 連続失敗カウンタ参照 = ユーザーID OR 共通トークルームID
data 対象月 = 年月
```

## 4. 隣接コンテキストとの境界

| 隣接 | 関係 | 翻訳層 behavior |
|---|---|---|
| LINE Messaging API（外部システム） | Conformist（順応者）／ACL の薄い層 | `behavior LINE push API を呼び出す`（Flex Message 仕様に従う） |
| 標準メール送信プロバイダ（SMTP/SES、外部システム） | Conformist（順応者） | `behavior フェイルセーフメールを送信する`（標準 SMTP/SES API に従う） |
| 家計分析 | 顧客-供給者（上流: 月次レポートCSV確定イベントを供給） | （受信側翻訳層は本コンテキストの `behavior 月次レポートサマリを共通トークルームに配信する` ／ `behavior 月次レポート個人サマリを個人DMに配信する`） |
| 取引取込 | 顧客-供給者（上流: PDF 変換失敗・CSV フォーマット検証失敗・OAuth 失効を通知依頼／CSV 取込状態を参照） | `behavior リマインダーの停止を判定する`（CSV 取込完了状態の参照） |
| オンボーディング・認証 | 顧客-供給者（上流: ユーザーID／共通トークルームID／OAuth 失効通知依頼／通知機能有効化／テスト送信依頼を供給。下流: テスト送信イベント（配信確定）を世帯通知有効化記録へ供給、#590） | `behavior テストメッセージを送信する`／`behavior OAuth失効通知を個人DMに配信する` |
| マスタ管理 | 顧客-供給者（上流: LINE Channel 設定値を供給） | `behavior LINE Channel設定値を取得する` |

| # | 問題 | 該当箇所 | 対応 |
|---|---|---|---|
| 1 | Phase 0 がマスタ管理中心（§1.1.3 確定）という判定の妥当性: Phase 0 の 5 つのワークフロー（LINE 公式アカウント作成・Webhook 設定・Channel 設定値投入・許可リスト投入・seed 投入）がいずれも自然にマスタ管理のワークフローとして書けた。所有者軸（システム管理者視点）の一貫性が確認できた。 | 2.1 Phase 0 全体 | 現状で OK と判断する |

### 3.8 シナリオCで発見された問題

| # | 問題 | 該当箇所 | 対応 |
|---|---|---|---|
| 1 | **修正起点の責務の曖昧さ**: 取引修正画面の「表示（家計分析）」と「学習データ更新（自動分類・学習）」が 1 つの UX 操作（保存ボタン）で 2 コンテキストをまたぐ。ワークフロー記述では自然に分割できたが、実装時に「保存ボタン押下 → 自動分類・学習を呼ぶ → 完了後に家計分析を更新」という順序依存がある。コンテキスト境界は妥当だが、実装の協調パターンが必要。| 3.1 手動修正ワークフロー（自動分類・学習 + 家計分析）| コンテキスト境界は変更しない。Phase 4 でアプリケーション層（UseCase）の順序制御として対処する |
| 2 | **F-1 の data 表現の完全性確認**: 08b-ul-自動分類学習.md の加盟店学習ルール / Amazon商品キー学習ルール いずれも `ユーザーID AND ...` 形式で定義されており、F-1（完全個人別）がデータ構造レベルで正しく表現されている。ワークフロー記述（3.1〜3.7）でも `他のインプット: 加盟店学習ルール（per-user）` と明示できた。設計どおり。| 3.2 memorization 学習ワークフロー全体 | 現状で OK と判断する |

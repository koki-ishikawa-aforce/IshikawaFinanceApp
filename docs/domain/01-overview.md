# ドメイン発見 Phase 1: ドメインの輪郭

> このドキュメントは IshikawaFinanceApp のドメイン駆動設計（DDD）における戦略的設計の一次成果物である。
> SPEC駆動開発の前提となるドメイン理解を記録する。

## 1. ドメインの種別

**2人家族（夫婦）向けの家計簿・資産管理アプリケーション**

家計簿（収支管理）と資産管理（複数口座をまたいだ資産推移の把握）の両方を扱う。

## 2. 解決したい課題（Why）

- 夫婦の複数の銀行・証券口座をまたいだ資産推移を、自分で集計せずに把握したい
- クレジットカードを含む支出（決済経路が多様）を一元管理したい

## 3. アクター

| アクター | 説明 |
| --- | --- |
| 夫 | アプリの利用者。家計を妻と共同で管理する |
| 妻 | アプリの利用者。家計を夫と共同で管理する |

夫婦は対等な利用者として扱う。専用の「世帯管理者」のような上位ロールは設けない方針。

## 4. ユーザーゴール（達成したいこと）

優先度の高い順:

1. **支出を「目的別」に把握する**
   今月どれだけのお金を、どの目的（カテゴリ／費目）で支出しているかを把握したい。
2. **資産推移を時系列で把握する**
   現金・証券などの資産がどのように推移しているかを、月次・年次で把握したい。

## 5. ドメインエキスパート

夫婦自身（=アクター=ドメインエキスパート）。
専任のドメインエキスパートはいないため、夫婦間の合意がそのままドメイン仕様となる。

## 6. ここから読み取れる初期の示唆

Phase 1 のヒアリング結果から、以下の概念が早期に必要になることが示唆される。

- **カテゴリ／費目**：支出を「目的別」に把握するために必須。
- **資産種別**：現金 vs 証券のように、資産は種別ごとに区別して扱う必要がある。
- **所有者**：夫婦が対等な利用者である以上、各取引・各口座の「誰のものか／共有か」を扱う必要がある。
- **時系列スナップショット**：月次・年次の推移を扱うため、ある時点での資産状態を保持する仕組みが必要。

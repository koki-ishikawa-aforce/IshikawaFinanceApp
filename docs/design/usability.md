# わりまる 使用性(ユーザビリティ)の規範

利用者が迷わず・間違えず・少ない手数で目的を達成できるための規範。**レビューで違反を指摘できる粒度**で書く。

> **`DESIGN.md` との役割分担**
>
> - [`DESIGN.md`](../../DESIGN.md) = **見た目の規約**。デザイントークン・テーマ・アイコン・装飾。「正しい色か / 正しい書体か / 両テーマで成立するか」を扱う
> - 本ドキュメント = **使用性の規範**。「迷わないか / 間違えないか / 手数が少ないか / 支援技術で使えるか」を扱う
>
> トークンが正しく使われていても本ドキュメントには違反しうる(例: 正しいトークンで描かれた空状態が、次に何をすべきか示していない)。逆も同じ。
>
> 参照: [レビュー観点の体系](../review/README.md)、[ユビキタス言語](../domain/08-ubiquitous-language.md)、[プライバシー3段階ルール](../domain/01-overview.md)

## 1. 状態の網羅

画面・セクションがデータを表示するなら、**ローディング / 空 / エラー / 部分失敗 の 4 状態をすべて定義する**。定義しなかった状態は「何も出ない」という最悪の表示になる。

### 規範

- **1-1** データを取得して表示する UI は、`ローディング` `空` `エラー` の 3 状態に対応する表示を持つ。1 つでも欠けていれば違反
- **1-2** **空状態は次の行動を示す**。「〜はありません」で終わらせず、「なぜ空か」または「何をすれば埋まるか」を書く。ユーザーの操作で埋められない空(その月に取引が無い等)は、なぜ空かを書けば足りる
- **1-3** エラー状態には**再試行手段**を置く。読み込み失敗を文言だけで終わらせない
- **1-4** 複数のデータソースを 1 画面に並べる場合、**一部だけ失敗した状態**(部分失敗)を定義する。1 つの失敗で画面全体をエラーに倒すか、失敗したセクションだけをエラー表示にするかを決め、同じ画面内で混在させない
- **1-5** 表示の切り替わり(グラフ → 空状態など)は支援技術に通知する(§8-4)

### 違反例

```tsx
// 違反(1-1): ローディングと空は書いたが、エラーが無い。取得失敗時に何も出ない
{query.isLoading && <LoadingState />}
{items.length === 0 && <EmptyState>データがありません</EmptyState>}
{items.map(...)}
```

```tsx
// 違反(1-2): 次の行動が無い
<EmptyState>突合待ちの入金がありません</EmptyState>

// 適合: 何をすれば埋まるかを示している
<EmptyState>突合待ちの入金がありません。先に「精算入金を記録」してください。</EmptyState>
```

```tsx
// 違反(1-3): 再試行できない
{query.error && <ErrorState>取引一覧の取得に失敗しました</ErrorState>}

// 適合(再試行手段は ErrorState の外に置く)
{query.error && (
  <>
    <ErrorState>取引一覧の取得に失敗しました</ErrorState>
    <button className={ui.buttonGhost} onClick={() => void query.refetch()}>再読み込み</button>
  </>
)}
```

## 2. プライバシー3段階の UI 表現

ドメインの [プライバシー3段階ルール](../domain/01-overview.md) を、**「見えない」ことが意図的だと利用者に伝わる形**で表現する。

| 費用区分 | 本人 | 相手 | UI での表現 |
| --- | --- | --- | --- |
| 世帯 | 明細 + 合計 | 明細 + 合計 | 区別なし |
| 個人(夫 / 妻) | 明細 + 合計 | **合計のみ** | 合計を出し、明細が意図的に非公開であると明示する |
| 経費(会社) | 明細 + 合計 | **合計すら不可視** | 相手の画面には**存在自体を出さない**(これが唯一の正しい「黙って空」) |

### 規範

- **2-1** 権限で明細が見えない値を**黙って空欄・ゼロ・ハイフンにしない**。「合計のみ公開」であることが分かるラベル(例: `(合計のみ)`)または補足を併記する
- **2-2** 相手の個人明細を開こうとしたとき、**権限による制限であることを文言で伝える**。汎用のエラー・空状態に落とさない
- **2-3** 経費(会社) は例外。相手の画面に「経費があるが見えない」ことを示唆する表示を出してはならない(合計すら不可視 = 存在を漏らさない)。セクションごと出さない
- **2-4** 相手の値を表示する箇所は、色だけでなくロール識別アイコン + ニックネームを併記する(`DESIGN.md` §4 ロール識別アイコン)
- **2-5** プライバシー段階の判定を UI 側で再実装しない。API が返す値(null 等)に従う。判定ロジックはドメイン層の ViewerContext に集約する(`/ddd-review` の観点と重複させないため、UI レビューでは「API の判定結果に従っているか」だけを見る)

### 違反例

```tsx
// 違反(2-1): 明細が null のとき黙ってハイフン。制限なのか未入力なのか分からない
<td>{tx.merchantName ?? '-'}</td>

// 違反(2-2): 権限制限を汎用エラーに落としている
{tx.amount === null && <ErrorState>データを取得できませんでした</ErrorState>}

// 適合
<EmptyState>配偶者の個人取引のため、詳細の閲覧・編集はできません</EmptyState>
```

## 3. ユーザーエラーの防止

### 規範

- **3-1 破壊的・不可逆な操作には確認を挟む**。対象は削除、最終確定、リマップを伴うマスタ削除、按分子取引の生成など、取り消せない操作すべて
- **3-2** 確認の文言には**何が起きるか**を書く。「削除しますか？」だけでは不足で、対象と影響(例: 学習ルールも消えるか、他の取引に付け替わるか)を示す
- **3-3** 確認 UI は §6-1 の採用パターンに従う。`window.confirm` と自前ダイアログを混在させない
- **3-4 バリデーションは送信を試みた時点、または入力から離れた時点で出す**。入力途中の 1 文字目でエラーを出さない
- **3-5** 送信ボタンは無効条件が満たされている間 `disabled` にし、**なぜ押せないかを画面上で分かるようにする**。`disabled` だけで理由を示さないのは違反
- **3-6** エラー文言は**次の行動を示す**。「エラーが発生しました」「不正な値です」で終わらせず、何をどう直せばよいかを書く
- **3-7** 送信中は多重送信を防ぐ(`isPending` で `disabled`)。かつ進行中であることを文言で示す(例: `登録中...`)

### 違反例

```tsx
// 違反(3-2): 影響が書かれていない
window.confirm('この取引を削除しますか？')

// 違反(3-5): 押せない理由が画面上に無い
<button disabled={!valid}>登録</button>

// 違反(3-6): 次の行動が無い
<ErrorState>不正な値です</ErrorState>
// 適合
<ErrorState>金額は1円以上の整数で入力してください</ErrorState>
```

## 4. 入力負荷

LIFF スマホ縦画面・片手操作が前提(`DESIGN.md` §1)。

### 規範

- **4-1 金額入力は `type="text"` + `inputMode="numeric"` にする**。`type="number"` は使わない(小数・`e`・`+/-` を受け付け §4-2 に反するほか、スクロールで値が変わるブラウザがある)。日付は `type="date"`、数値以外の数字列(口座番号など)も `inputMode` を明示する。モバイルキーボードの切り替えを利用者にさせない
- **4-2** 金額に小数を使わない(円単位)。小数キーが出る指定をしない
- **4-3 タップターゲットは最小 44×44 px を確保する**。`padding` だけに頼らず、`min-height` で保証する。アイコンのみのボタンは特に確認する
  - 値は `--tap-target-min`(`packages/web/src/app/globals.css`)を参照する。`min-height` はレイアウト用途と区別できず stylelint で縛れないため、共通の操作部品については `packages/web/src/test/tap-target.test.ts`(宣言)と `packages/web/e2e/tap-target.spec.ts`(描画後の実寸)が機械的に検出する
- **4-4** 並んだタップターゲットの間隔を最低 `--space-2` 確保する。誤タップを防ぐ
- **4-5** 主要操作は**画面下部 1/3 に置く**(片手の親指が届く範囲)。長いフォームの送信ボタンを画面最上部に置かない
- **4-6** 既定値を埋められる入力は埋める(対象月 = 表示中の月、発生日 = 当日など)。毎回同じ値を手で入れさせない
- **4-7** 選択肢が 2〜3 個の場合はセレクトではなくトグル / セグメントにする。タップ数を減らす

### 違反例

```tsx
// 違反(4-1): 数値キーボードが保証されず、小数・e も入力できてしまう
<input type="number" value={amount} onChange={...} />
// 適合: type="text" + inputMode で数値キーボードを出し、値の検証はバリデーションで行う
<input type="text" inputMode="numeric" value={amount} onChange={...} />
```

```css
/* 違反(4-3): 8px パディング + 12px フォント = 約 30px。44px に届かない */
.button {
  padding: var(--space-2) var(--space-3);
  font-size: var(--text-sm);
}
/* 適合 */
.button {
  min-height: var(--tap-target-min);
  padding: var(--space-2) var(--space-3);
  font-size: var(--text-sm);
}
```

## 5. マイクロコピー

### 規範

- **5-1 UI 文言はユビキタス言語と一致させる**([`docs/domain/08-ubiquitous-language.md`](../domain/08-ubiquitous-language.md) および BC 別 08a〜08h)。勝手な同義語を作らない
  - 例: ドメイン用語が「配偶者」なら UI も「配偶者」。ただし利用者向けの通称が定義されている場合(`DESIGN.md` の「パートナー」)はそれに従い、**どちらを使うかを画面内で混在させない**
- **5-2** アプリ名は **わりまる**。「割りまる」は誤表記(`CLAUDE.md`)
- **5-3 金額は 3 桁区切り + 「円」**。`¥` と `円` を混在させない。負値の表現(`-1,000円`)を画面ごとに変えない
- **5-4 日付・時刻は JST で表示する**。年月は `2026年7月`、日付は `2026/07/25` の形式に統一する。UTC の値をそのまま出さない
- **5-5** 状態バッジ(暫定 / 確定 / 未分類 など)の呼称をユビキタス言語に合わせ、画面間でぶれさせない
- **5-6** 専門用語(按分、消込、発生主義、リマップ)を利用者向け UI にそのまま出す場合、初出箇所で 1 行の補足を付ける
- **5-7** ボタンラベルは**動作**を書く(`OK` ではなく `最終確定する`)。進行中の文言も動作に対応させる(`確定中...`)

### 違反例

```tsx
// 違反(5-3): 記号と単位が混在
<span>¥{amount}</span>
<span>{other}円</span>

// 違反(5-4): UTC のまま
<span>{new Date(iso).toISOString()}</span>

// 違反(5-7): 何が起きるか分からない
<button>OK</button>
```

## 6. インタラクションパターンの一貫性

同じ目的に複数のやり方を混在させない。**採用パターンは以下に限る**。新しいパターンを増やす場合は本節に追記してからにする。

| 目的 | 採用パターン |
| --- | --- |
| **6-1 破壊的操作の確認** | `Modal`(`packages/web/src/components/ui/Modal.tsx`)で確認する。`window.confirm` は使わない |
| **6-2 操作結果の通知** | 成功はその場の表示更新で示す(専用の成功トーストは置かない)。失敗はその操作の直下に共通部品 `ErrorState`(`packages/web/src/components/ui/ErrorState.tsx`)で出す。トースト / スナックバーは採用しない。`*.module.css` に独自のエラースタイルを定義しない |
| **6-3 フォームの保存方式** | 明示保存(送信ボタン)。自動保存・フィールド単位保存は採用しない |
| **6-4 フォームの提示** | 一覧からの追加・編集は `Modal`。ページ遷移させない |
| **6-5 ローディング** | 共通部品 `LoadingState`(`packages/web/src/components/ui/LoadingState.tsx`)によるセクション単位のインライン表示。全画面スピナー・スケルトンは採用しない。`*.module.css` に独自のローディングスタイルを定義しない |
| **6-6 空状態** | 共通部品 `EmptyState`(`packages/web/src/components/ui/EmptyState.tsx`)。インラインのテキストで、イラスト・空状態専用カードは採用しない。置き場所はその空状態が説明するセクションの器(`ui.card` かモーダル)の内側。`*.module.css` に独自の空状態スタイルを定義しない |
| **6-7 月の切り替え** | 画面上部の月ナビゲーション。日付ピッカーで月を選ばせない |
| **6-8 補足情報・手順の格納** | カード内の開閉トグル(見出しが `aria-expanded` + `aria-controls` を持つボタンを包む)。主操作の前に読まなくてよい補足はこれで畳む。モーダル・別ページ・常時展開は採用しない |
| **6-9 2〜3 択の選択** | 共通部品 `SegmentedControl`(`packages/web/src/components/ui/SegmentedControl.tsx`)。中身はラジオで、選択状態が `checked` として伝わる(§4-7)。セレクト・独自のタブ風ボタンは採用しない。選択肢が 4 つ以上になる場合はセレクト(`ui.select`)に戻す。本部品より前からある未追随の箇所が 2 つある。ダッシュボードの世帯/個人切り替え(`components/dashboard/ModeToggle.tsx`)は独自実装でタップ下限(§4-3)も満たしておらず、#366 でそこを直すときに本部品へ寄せる。口座追加の証券会社(3 択、`components/accounts/AccountAddModal.tsx`)はセレクトのままで、次にその画面を触るときに本部品へ寄せる |

### 違反例

```tsx
// 違反(6-1): Modal がある画面で window.confirm を使っている
if (window.confirm('この取引を削除しますか？')) remove.mutate()

// 違反(6-3): onChange で即保存している
<input onChange={e => void save.mutate(e.target.value)} />
```

## 7. LIFF / モバイル固有

`packages/web` は Next.js 15 Static Export。**HTML にデータは含まれず、表示後にクライアントから取得する**。この制約に由来する体験を明示的に扱う。

### 規範

- **7-1** LIFF 初期化中は**内容を確定できない領域を空のまま見せない**。初期化完了までローディング状態を出す(§1-1)
- **7-2 クライアントフェッチによる表示のちらつきを許容しない**。「0円 → 実値」「空状態 → データ」のように**確定前の値を一瞬見せてから差し替える実装をしない**。未取得はローディング状態として表示する
- **7-3** 通信失敗時は §1-3 に従い再試行手段を出す。LIFF の WebView は電波状況が不安定な前提で設計する
- **7-4** 横画面・タブレット・PC のレイアウト最適化はしない(`DESIGN.md` §1)。ただし**縦画面で内容が切れる・横スクロールが発生するのは違反**
- **7-5** モーダルを開いている間、背後のページがスクロールしないようにする(WebView でのスクロール貫通を防ぐ)
- **7-6** 認証切れ・許可リスト外を汎用エラーに落とさず、それぞれ専用の文言で表示する

### 違反例

```tsx
// 違反(7-2): 未取得を 0 として描画してから実値に差し替わる(ちらつき)
const total = query.data?.total ?? 0
return <span>{formatMoney(total)}</span>

// 適合
if (query.isPending) return <LoadingState />
return <span>{formatMoney(query.data.total)}</span>
```

## 8. アクセシビリティ(`DESIGN.md` に無い分)

`DESIGN.md` §6 は `aria-label` / `aria-hidden` / 色だけに頼らない識別を定めている。本節はそこに**無い**観点を補う。重複して指摘しないこと。

### 規範

- **8-1 フォーカスの可視化**: キーボード / 支援技術で操作しうるすべての要素(`button` `a` `input` `select` `textarea`)にフォーカスの可視スタイルを付ける。`outline: none` で消して代替を用意しないのは違反
- **8-2 フォーカス順序**: DOM 順が視覚順と一致すること。`tabIndex` に 0 / -1 以外の正の値を使わない
- **8-3 フォームのラベル関連付け**: `<label>` は `htmlFor` + `id` で対応する入力に関連付ける(または入力を `<label>` で包む)。**見た目だけラベルに見える兄弟要素は違反**
- **8-4 動的更新の通知**: ユーザー操作やデータ更新で内容が差し替わる領域(月の切り替えによるグラフ ⇄ 空状態、保存結果、エラー表示)は `role="status"`(`aria-live="polite"`)、致命的なものは `role="alert"` で通知する。ページ遷移を伴わない更新は読み上げが発生しないため、指定が無ければ違反
- **8-5 見出し階層**: ページに `<h1>` を 1 つ置き、セクション見出しは `<h2>` 以降を使う。**見た目だけ見出しに見える `<span>` / `<div>` は違反**。階層を飛ばさない
- **8-6 コントラスト比**: 本文 4.5:1、大きい文字(18px 以上 / 14px 太字以上)3:1 以上。**darling / honey 両テーマで満たすこと**。半透明背景(`rgba(255,255,255,0.7)` 等)の上に淡色テキストを置く場合は実効値で判定する
- **8-7 モーダルの支援技術対応**: `role="dialog"` + `aria-modal="true"` + `aria-labelledby` でタイトルを関連付ける。開いたときフォーカスをモーダル内へ移し、閉じたとき呼び出し元へ戻す。Esc で閉じられること
- **8-8 画像・アイコンのみのボタン**: `aria-label` を付ける(`DESIGN.md` §6 と同じ規範。ここでは再指摘しない)

### 違反例

```css
/* 違反(8-1): button に focus スタイルが無い(hover しか無い) */
.button:hover {
  opacity: 0.85;
}
```

```tsx
// 違反(8-3): label と input が兄弟で、関連付けが無い
<div className={ui.field}>
  <label className={ui.fieldLabel}>金額（円）</label>
  <input className={ui.input} type="number" />
</div>

// 適合
<div className={ui.field}>
  <label className={ui.fieldLabel} htmlFor="amount">金額（円）</label>
  <input className={ui.input} id="amount" type="text" inputMode="numeric" />
</div>
```

```tsx
// 違反(8-5): 見た目だけ見出し
<span className={ui.sectionTitle}>精算サイクル</span>
// 適合
<h2 className={ui.sectionTitle}>精算サイクル</h2>
```

# 判断依頼テンプレート

人間の判断が必要になったときの本文フォーマット。用途は3つ:

- **撤退時の確認**(受け入れ条件が曖昧・設計判断が分かれる・CI が直せない・マージゲートに落ちた): 元 Issue への**コメント**として使う
- **見送り追認**(/ddd-review の suggestion 見送りなど): **新規 Issue** として使う
- **改善案・乖離報告**(/retro・/docs-drift): **新規 Issue** として使う

いずれも `needs-decision` ラベルを付与する。SKILL.md の「人間向け報告の執筆ルール」を必ず適用する。以下の `<!-- -->` は書き方の指示であり、出力には含めない。

> マージ可否は判断依頼の対象ではない。ゲートを満たす PR は無人モードが自分でマージする(`.claude/skills/issue-work/SKILL.md`「マージゲート」)。ゲートに落ちた PR は「撤退時の確認」として元 Issue に集約する。

## タイトルの種別目印(必須)

判断待ち Issue のタイトル**先頭**に、種別を表す目印を必ず付ける。メールの件名には Issue タイトルがそのまま入るため、この目印だけで「自分が何をする種類の依頼か」が開かずに分かる。目印は次の4種:

| 目印         | 用途                                         | 起票するもの                            | タイトル例                  |
| ------------ | -------------------------------------------- | --------------------------------------- | --------------------------- |
| `[判断待ち]` | 撤退時の確認・見送り追認・重複 PR などの判断 | issue-work / pr-steward / backlog-ready | `[判断待ち] <要約>`         |
| `[乖離報告]` | docs とコードの乖離報告                      | docs-drift                              | `[乖離報告] <乖離の要約>`   |
| `[改善案]`   | 無人運用の失敗パターンからの改善提案         | retro                                   | `[改善案] <改善対象の要約>` |
| `[main 赤]`  | マージ後の `main` の CI 失敗                 | `.github/workflows/ci.yml`(bot)         | `[main 赤] <要約> (<sha>)`  |

- `[main 赤]` だけは Claude ではなく GitHub Actions が起票する。本文フォーマットもワークフロー側に固定で書かれているため、このテンプレートの適用対象外(消化手順は `/decide` 手順3d)。
- **元 Issue へのコメント**で判断を仰ぐ場合(撤退時の確認など、既存 Issue のタイトルを変えないケース)は、タイトルに目印を付けられないため付けない。この場合、通知ワークフローは種別を判別できず**共通文にフォールバック**する(下記「通知」参照)。
- 旧 `[マージ判断]` 目印とマーカー `<!-- merge-judgment-pr: <PR番号> -->` は廃止した。新規には使わない(過去に起票済みの Issue を回収するため、通知ワークフローとスキル側の処理は残してある)。

## 通知(補足)

`needs-decision` の付与をトリガーに `.github/workflows/notify-needs-decision.yml` がオーナーを assign し、@メンションコメントで「あなたがすること」の1行を通知する。この1行は**タイトル先頭の目印から種別を判別**して出し分けられる(目印が無ければ共通文)。本文の「✅ あなたがすること」と食い違わないよう、下記フォーマットのアクションを簡潔に書く。
